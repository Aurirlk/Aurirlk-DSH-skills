# 前端交付方法论

这个技能不教怎么写 Vue —— 具体写法（`useTable`、扁平请求、`columns` 必须是函数）在 **vue3-admin-frontend** 里。

这里管的是**推进顺序和判断**：什么时候该停下先问、哪个现象说明问题不在前端、什么顺序改才不会返工。

一句话概括：

> **前端最大的时间浪费不是写代码慢，是在错误的层上找问题。**

## 一、开工前必须问清的三件事

不问清就开始写，后面每一件都会以"返工"的形式收费。

### 1. 这个页面的后端，具体在哪？

不是"我们有后端"，而是：**哪个网关、哪个环境、路径前缀是什么**。

踩过的坑：同时存在三个"管理端"——平台管理端、微服务管理端、业务前端。它们端口不同、后端不同、有的起有的没起。用户说"登录失败"，第一反应如果是"前端 bug"，就白找两小时。

必问：`环境地址 + 路径前缀 + 是否需要 proxy rewrite`。三者缺一，请求就会打空。

### 2. 接口定稿了吗

DTO 还在改的时候写页面，等于给一个会动的靶子画框。判定方法：让后端给出**字段名、类型、必填与否、枚举取值**。拿不到就别急着写表单。

### 3. 这个页面要覆盖哪些状态

只写"正常态"是新手最容易犯的错。开工就列清单：

- 空（没有数据 / 首次进入）
- 加载（首屏、翻页、提交中）
- 错（接口失败、超时、无权限）
- 极端（超长文本、超大表格、字段为空）
- 恢复（重试、返回、刷新后状态还在不在）

这五类每类至少一句话文案。事后补的代价是每补一处都要动一遍模板。

## 二、环境「跑通」有三个级别，别把 L1 当成功

| 级别 | 判据 | 常见假象 |
| --- | --- | --- |
| **L1 起得来** | `pnpm dev` 无报错，浏览器能打开页面 | 依赖装歪了也能开个白屏 |
| **L2 登录得上** | 能拿到 token/会话，进得去主界面 | 后端 502，页面自己弹了个假欢迎页 |
| **L3 拿得到数据** | 列表能出真实数据，不是空数组 | 接口 401 被空态吞掉，看着"就是没数据" |

**L1 通过就说"环境好了"是最常见的误判。**

三个探针，按顺序打：

```bash
# 探针 1：绕开前端，直接问后端活着没
curl -i "<后端地址><前缀>/system/auth/login"      # 401/200 都算活；502/000 是死

# 探针 2：看请求到底打到哪（浏览器 devtools → Network）
#   看 Request URL 的 host 和前缀，是不是你以为的那个

# 探针 3：比对两边前缀
#   axios base_url 的前缀  ==  vite proxy 的匹配前缀？
#   不一致 → 请求根本不走 proxy，直接打到前端自己 404
```

探针 3 是最隐蔽的：`base_url = /admin-api` 而 proxy 只匹配 `/gw-api`（或反过来），请求就不走 proxy，浏览器里表现是 404，人却在查后端日志。

## 三、本地配置脱管：用 `.env.*.local`，别动已跟踪的文件

想把本地配置改成连自己机器、又不想影响同事，**不要** `git rm --cached .env`——那会产生一次删除提交，别人拉下来文件就没了。

正确做法：

```
.env.<mode>.local          # Vite 优先级最高，且 *.local 天然被 gitignore
```

Vite 的加载优先级是 `.env.<mode>.local` > `.env.<mode>` > `.env.local` > `.env`。所以只要项目 `.gitignore` 里有 `*.local`（大多数模板都有），新建一个 `.env.base.local` 就同时满足"生效"和"不脱管"，**零提交、零影响**。

验证方式不要靠眼睛：

```bash
git check-ignore -v .env.base.local     # 必须命中某条 ignore 规则
git status --short                      # 应该看不到这个文件
```

顺手在 `.gitignore` 里补显式规则（`.env.*.local`、`.env.local`），防止同事用 `-f` 强推。

**多个项目并存时特别小心**：老项目与新项目的 env 路径体系可能完全不同（一个直连网关、一个走公网 nginx 改写），配置不能互相抄。判断依据永远是 `vite.config.ts` 里的 proxy 前缀 + `axios base_url`，不是"上次那个能跑"。

## 四、依赖要锁死，别让它自己漂

前端依赖最大的风险不是"版本旧"，是**传递依赖悄悄升到一个改了 `exports` 的版本**。

真实形态：某库声明 `"@zip.js/zip.js": "^2.7.34"`，装上来的却是 2.23.0（满足范围的最新版），而新版**从 `exports` 里移除了某个子路径** → Vite 预打包报 `Missing "./lib/xxx.js" specifier`，整个 dev 起不来。

诊断三步，顺序别倒：

```bash
# 1. 谁在依赖它、声明的范围是什么
grep -r "zip.js" node_modules/@cesium/engine/package.json

# 2. 实际装的是哪个版本
cat node_modules/@zip.js/zip.js/package.json | grep '"version"'

# 3. 那个版本还有没有这个子路径
node -e "console.log(Object.keys(require('./node_modules/@zip.js/zip.js/package.json').exports))"
```

三步一比，结论就出来了：**声明允许、实际装了新版、新版删了子路径**。

修法优先级：`overrides` 钉回兼容版本 > `resolve.alias` 把子路径指到等价入口 > 降级包管理器。用 alias 时**必须核实目标入口的 API 是否齐全**（有些"看起来等价"的文件其实是空占位）。

### pnpm 10 → 11 的两个硬变化

- **`strictDepBuilds` 默认 true**：未审批的 `postinstall` 直接让整个 install 失败（10 只警告）。配置项从 `onlyBuiltDependencies` 换成了 `allowBuilds`，写在 `pnpm-workspace.yaml`。
- **`allowBuilds` 对 git 依赖必须写 URL，不能只写包名**。官方明确：单独的包名永远不批准 git/tarball 依赖的构建脚本。要写成 `pkg@git+<url>` 这种形式，且匹配是**精确匹配**（`git+ssh://` 与 `git+https://` 算不同 key）。

还有一个连锁坑：`package.json` 顶层 `"pnpm": {"overrides": ...}` 在 pnpm 11 **不再被读取**（只报 WARN）。override 不生效时，表现是"我明明改了版本，装出来还是旧的"——先确认它有没有真的生效，再查别的。

## 五、契约同步：顺序倒了就会淹在报错里

```
DTO/字段 → 前端类型 → API 函数 → 页面 → i18n → 路由 → 验证
```

先改页面再改类型，`vue-tsc` 会一次报十几个"属性不存在"，真正的问题被埋掉。具体每一处该改什么，见 **vue3-admin-frontend** 的「后端改 DTO 前端动七处」。

## 六、多语言：真实成本是「8 套 × 2 个类型文件」

这个项目的语言包是 8 套（zh-cn、zh-tw、en-us、vi-vn、th-th、id-id、ms-my、fil-ph），不是中英两套。

**新增一个 key 要动的地方：**

1. 8 个语言包文件（`src/locales/langs/*.ts`）
2. `src/typings/app.d.ts` 里的 `I18n.Schema`（**手写 interface，不自动生成**）
3. 有的项目还有 `src/typings/extra.d.ts`（页面级 key）
4. 用到的地方 `$t('key')`

「缺一即未完成」在这里是字面意思：漏了类型表，`vue-tsc` 在**每个**使用处报错；漏了某个语言包，那个语言下界面直接显示 key 原文。

**排查时的致命陷阱**：只 `grep "中文串"` 会漏掉 7 个文件——因为只有 zh-cn 用中文，其余语言里同一 key 是英文/越南语/泰语。要按 **key 名**搜，不按键值搜：

```bash
# 正确：按 key 搜全量语言包
grep -rn "route.dataAgent" src/locales/langs/
# 错误：按中文值搜，只能命中 zh-cn
grep -rn "数据智能体" src/locales/langs/
```

## 七、布局先定「谁滚」，再谈样式

全屏应用（对话框、编辑器、看板）最常见的 bug 不是样式丑，是**输入框被顶出视口**。根因几乎总是同一类：**高度在某一层断了**。

### 高度链为什么会断

`h-full` 依赖祖先每一层都有确定高度。中间任何一层是 `auto`（被内容撑开），链就断了——顶层的 `h-full` 退化成 `auto`，内容一多就把下面推出去。

三种常见断点：布局组件的 `<main>` 用了 `flex-grow` 但没定高、主题/布局模式切换后 footer 占位变了、`KeepAlive` 切回来时尺寸缓存过期。

### 三条判断，照这个顺序查

1. **别只在页面内部加 `min-h-0`**。断点在页面外那一层时，页面内怎么调都没用。先确认祖先链有没有一个是 `auto`。
2. **要算高度就用视口算，不要用父元素的 `clientHeight`**。父被内容撑高时，拿它的高度会正反馈（越撑越高）。正确基准是 `documentElement.clientHeight` 减去顶部偏移和 footer。
3. **高度是动态的就要监听**：`ResizeObserver` + `window.resize` + `onActivated`（KeepAlive 切回），并在 `onBeforeUnmount` 清理。写入前先比值，**值没变就不要写 ref**，否则 RO 会自触发成死循环。

### 滚动链：不要手写 wheel 劫持

- **`overscroll-behavior: contain` 会把滚动链掐死**。内层一旦不可滚（内容不够长、高度算错），滚轮就变成死区，用户以为页面卡了。
- 想要「默认滚内层、内层滚到头再滚外层」，用 `auto` 让浏览器原生处理。
- 有一个好用的 CSS 事实：`overflow-x: hidden` + `overflow-y: visible` 时，规范要求把 `visible` 计算成 `auto` —— 于是纵向天然保留"可滚但通常不出现滚动条"的能力，正好当第二层兜底。
- **不要手写滚轮事件去改 `scrollTop`**：原生滚动链已经处理好惯性、触控板、缩放，手写十次有九次是双倍滚动。

## 八、数据流：三个响应性陷阱

### 1. push 进去的对象，改了不触发更新

```js
const reply = { role: 'assistant', text: '' }
s.msgs.push(reply)          // 数组是响应式的，但推进去的是原始对象
reply.text += chunk         // ❌ 改的不是代理，界面一帧都不动
```

表现极具迷惑性：**流式输出期间界面完全不动，等某个真 ref 变化时才"一股脑全蹦出来"**——看起来像"卡了几秒"，其实是根本没触发渲染。

```js
s.msgs.push(reply)
const r = s.msgs[s.msgs.length - 1]   // ✅ 取回响应式代理
r.text += chunk
```

判断方法：如果"过一会儿突然全出来"，先怀疑响应性，别怀疑网络。

### 2. 列表 key 不能用服务端自增 id

草稿态（还没落库）的 id 是 0 或 undefined，多条草稿会撞同一个 key → 选中态乱跳、删错行。

正确做法是**两个 id 分开**：`key`（前端生成的唯一标识，用于列表 key 和选中态）、`id`（服务端 id，0 表示未落库）。落库拿到真 id 后再回填，但 `key` 不变。

### 3. 流式增量：空串和空白字符是两件事

后端把 `"\n"`、`" "` 这种**单独成帧**的增量用 `isBlank()` 过滤掉，累积正文里一个换行都没有 → markdown 的标题、表格、分隔线全部失效，只有行内粗体还在，看着像"markdown 只渲染了一半"。

判定：`isEmpty()`（只判 null/空串）用于内容增量；`isBlank()`（含纯空白）只用于"模型是否真的开口了"这类判断。这两个语义不能混用。

前端能自保的一层：渲染前 normalize，给粘连的表格行、紧贴正文的 `---` 补空行（逐行扫描，跳过代码围栏）。注意 `breaks: true` 下表格本来就能打断段落，真正需要补的是 `---` 被误判成 setext 标题的情况。

## 九、巨型组件：6000 行不是勤奋，是负债

实测规模：单文件组件涨到 6229 行、详情页 4679 行。到这个体量，任何改动都要在一屏之外找上下文。

拆的顺序（**从低风险到高风险，别跳**）：

1. **先抽无状态展示**：纯 props 进、事件出的卡片/列表项。风险最低，改坏了一眼能看出来。
2. **再抽数据 hook**：把"取数 + 分页 + loading"搬进 `useXxx()`。模板不用大动。
3. **最后拆状态机**：把散落的布尔量（`sending`/`loading`/`typing`/`done`）收敛成一个枚举。这一步最容易出错，放最后。

不要为了"文件小"而拆。判断标准是：**这个块有没有独立的输入输出**。有就值得抽，没有就只是把代码搬到另一个文件，反而多了一层跳转。

另一个信号：**状态只建模了 3 个，但业务需要 8 个**。这时先补状态模型，再谈拆分——否则拆出来的每个组件都缺状态。

## 十、死代码：前端特有的「假完成」

后端有编译器和静态检查挡着，"写了没接线"不容易活太久。前端不一样，下面这些都能通过 `typecheck` 和 `lint`：

| 形态 | 例子 |
| --- | --- |
| prop 从来没被传过 | 组件里渲染红点，但调用方 `<Comp />` 从不传 `count` → 红点恒 0 |
| 封装好的接口没人调 | `fetchPendingChanges()` 写完了，打开面板时不调 |
| 事件回调没接 | 流式接口支持 `onThinking`，但调用方没传 → 推理内容被静默丢弃 |
| 按钮没有 `@click` | 图标在那、样式对、点了没反应 |
| 占位文案指向不存在的功能 | placeholder 写"输入 / 调用技能"，但压根没实现这个语法 |

交付前扫一遍：**每个新增的 prop、接口函数、事件回调，找到它的调用点**。找不到就是没接线。

## 十一、验证与交付

### 三道自动检查，看的是「基线」不是「有没有」

```bash
pnpm typecheck     # 必须 0 错
pnpm lint          # 看 error 数 + warning 是否超出历史基线
pnpm build         # 能产 dist 才算过；dev 能跑不代表能构建
```

warning 有历史存量是正常的，关键是**别让它涨**：改之前记下基线（例如 0 error / 44 warning），改完必须回到同一个数。新增的行里出现告警，就是自己引入的。

### 然后真的打开看一眼

`typecheck` 通过、`lint` 通过、`build` 通过，页面仍然可能是错的——布局被撑开、按钮点不动、空态没写。这三道检查只保证"代码合法"。

**"dev 能开"不等于"页面对"。** 至少走一遍：进入 → 加载 → 有数据 → 空数据 → 报错 → 返回。

### 改完为什么有时看不到变化

三种可能，按概率排：

1. **看的是旧静态包**：`dist` 没重新构建或没重新部署。改源码对已部署的页面无效。
2. **浏览器缓存**：强刷（Ctrl+F5 / 无痕窗口）。
3. **服务端缓存**：中间层或 CDN 缓存了旧资源，需要在 URL 上加版本参数或用不同路径。

交付时把这三条写进说明，别让用户自己在"为什么没变化"上耗时间。

### 交付要说清的三件事

1. **后端依赖**：这个页面依赖哪些接口/环境，后端没起来时页面会表现成什么样（空态？报错？白屏？）
2. **构建产物**：`dist` 在哪、用什么 mode 构建的、要不要清缓存
3. **未验证的部分**：本地没起服务、没真机测、没测某个语言——明确说"没验"，别用"应该没问题"

## 排障决策树

| 现象 | 先查这一层 | 判据 |
| --- | --- | --- |
| 页面白屏 / 打不开 | 构建产物与路由 | Console 有没有 chunk 加载失败；路由是否匹配到 404 |
| 登录不上 | **后端活着吗** | 先 `curl` 接口；502 = 后端死，401 = 后端活但凭据不对 |
| 接口 404 | **前缀是否对齐** | axios base_url 前缀 vs proxy 匹配前缀 vs 后端真实前缀，三者比对 |
| 接口 401 | 凭据传递 | 请求头里有没有 token；是不是跨域被剥掉了 cookie |
| 列表一直空 | 响应结构 | devtools 看响应体：是空数组，还是 `{code, data}` 包了一层没取到 |
| 流式卡几秒才全出来 | **响应性** | 见 §八.1，改的是不是代理对象 |
| markdown 只渲染一半 | 增量是否丢空白 | 累积正文里有没有 `\n` |
| 输入框被顶出视口 | **高度链** | 祖先链有没有一层是 `auto`；别只加 `min-h-0` |
| 内层滚不动、滚轮像死区 | `overscroll-behavior` | 有没有 `contain` 掐断滚动链 |
| 改了代码没变化 | 构建 / 缓存 | 是不是旧 dist、有没有强刷 |
| 某个语言显示 key 原文 | 语言包漏了 | 按 key 名搜 8 个语言包，不是按键值搜 |
| `vue-tsc` 报 key 不存在 | 类型表漏了 | `app.d.ts` 的 `I18n.Schema`（可能还有 `extra.d.ts`） |

这张表的用法是：**先定位层，再动手**。跳过定位直接改代码，八成改在错的地方。
