# frontend-delivery-method

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

前端交付方法论：从「后端给了个接口」到「用户真能用」。

## 这玩意儿治什么

> **前端最大的时间浪费不是写代码慢，是在错误的层上找问题。**

一次真实经历：用户说"登录失败"，第一反应是查前端登录逻辑。查了两小时才发现——本机同时跑着三个"管理端"，各自连不同的后端，其中一个后端远端 502、另一个压根没起。**前端代码一行没错。**

这个技能不讲怎么写 Vue（那是 [vue3-admin-frontend](../vue3-admin-frontend/README.md) 的事），讲的是**推进顺序和判断**：

- 开工前必须问清什么，不问就会返工
- "环境跑通了"分三个级别，L1 不等于能用
- 出现某个现象时，**先查哪一层**
- 什么顺序改才不会淹在报错里

## 七条主线

**1. 开工三问** — 后端在哪台机（网关/环境/前缀）、接口定稿了没、页面要覆盖哪些状态（空/加载/错/极端/恢复）。只写正常态是新手最容易犯的错。

**2. 环境三级** — `dev` 起得来（L1）≠ 登录得上（L2）≠ 拿得到真实数据（L3）。三个探针：`curl` 直打接口、devtools 看请求打到哪、比对 `base_url` 与 proxy 前缀。第三个最隐蔽：前缀不匹配时浏览器报 404，人却在查后端日志。

**3. 配置脱管** — 想把本地配置改成连自己机器又不想影响同事，**别 `git rm --cached .env`**（会产生删除提交，同事拉下来文件就没了）。用 `.env.<mode>.local`：Vite 优先级最高，`*.local` 天然被 gitignore，零提交零影响。

**4. 依赖锁死** — 最大的风险不是版本旧，是**传递依赖悄悄升到改了 `exports` 的版本**。真实形态：某库声明 `^2.7.34`，装上来 2.23.0，新版删了个子路径 → Vite 预打包直接崩。诊断三步：声明范围 → 实际版本 → 该版本还有没有这个子路径。

**5. 契约顺序** — DTO → 类型 → API → 页面 → i18n → 路由 → 验证。顺序倒了，`vue-tsc` 一次报十几个错，真正的问题被埋掉。

**6. 布局先定谁滚** — 输入框被顶出视口，根因几乎总是**高度链在某一层断了**。别只加 `min-h-0`（断点在页面外时没用），算高度用视口别用父元素（会正反馈），`overscroll-behavior: contain` 会把滚动链掐成死区。

**7. 验证要真的看一眼** — `typecheck`/`lint`/`build` 全过，页面仍然可能是错的。这三道只保证代码合法。

## 三个真踩过的坑

**流式输出卡几秒，然后一股脑全蹦出来**

不是网络慢。`s.msgs.push(reply)` 推进去的是**原始对象**，之后 `reply.text += chunk` 改的不是代理，一帧都不触发；等某个真 ref 变化才整体重渲染。修法一行：push 完 `const r = s.msgs[s.msgs.length - 1]` 取回代理再改。

**markdown 只渲染了一半**

后端用 `isBlank()` 过滤增量，把单独成帧的 `"\n"` 全丢了 → 累积正文里一个换行都没有 → 标题、表格、分隔线规则全失效，只有行内粗体幸存。`isEmpty()`（只判空串）和 `isBlank()`（含纯空白）是两件事，不能混用。

**改了一个 key，界面在某种语言下显示原始字符串**

语言包是 **8 套**（中/繁/英/越/泰/印尼/马来/菲律宾），不是中英两套。而且类型表 `I18n.Schema` 是**手写的 interface**，不自动生成。
更坑的是排查方式：`grep "中文串"` 只能命中 zh-cn，另外 7 个文件里同一 key 是别的语言 —— **必须按 key 名搜，不能按键值搜**。

## 还有两节值得单独看

- **巨型组件怎么拆**：实测单文件涨到 6229 行。拆的顺序是「无状态展示 → 数据 hook → 状态机」，从低风险到高风险，别跳。先补状态模型再拆，否则拆出来每个组件都缺状态。
- **前端特有的假完成**：prop 从没被传过（红点恒 0）、封装好的接口没人调、事件回调没接（推理内容被静默丢弃）、按钮没 `@click`、placeholder 指向不存在的功能。这些**都能通过 typecheck 和 lint**。

## 什么时候会用到

- 接一个新页面 / 新项目，不知道从哪下手
- dev 起得来但登录不上、或者列表一直是空的
- 页面布局被内容撑开、输入框被顶出视口
- 改了代码但页面上看不到变化
- 一个 `.vue` 涨到几千行，想拆不敢动
- 交付前想确认"真的做完了"

## 它不管什么

- 不管具体框架语法（Vue/React 都能用这套过程）。
- 不管设计稿还原和视觉细节。
- 不管 CI/部署流水线的配置。
