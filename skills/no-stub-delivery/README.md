# no-stub-delivery

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

有三种东西长得像功能，但一碰就碎：

| 形态 | 表面 | 真相 |
|---|---|---|
| **假数据** | 页面有数据、图表有曲线 | 硬编码 / 随机生成 |
| **假实现** | 类在、接口在、配置在 | `return null` / `TODO` / 占位返回 |
| **假完成** | 文档写"已集成" | 代码里没有，或写了没人调用 |

它们的共同点：**看起来完成，实际不解决问题** —— 而且都能在演示里过关。这正是它们能活下来的原因。

## 什么时候用

- 交付前自检、写验收清单、上线检查
- 用户说"这功能根本用不了""数据是假的吧"
- 接手别人的代码，要判断哪些是真功能
- 要给一份状态报告，但不确定哪些能打勾

## 它治的核心问题

> **为了"看起来对"而撒谎，是最贵的一种省事。**

一次被认定糊弄，后面每句话都要被怀疑。所以这个技能的态度很硬：**看不到数据时补齐真实能力，而不是伪造数据。**

```
✗ 塞几行 mock 让下拉能选
✓ 加"上传本地文件"入口，复用真实上传接口拿真 URL

✗ 造一份假结果展示
✓ 明确显示"无数据"，并告诉用户怎么产生数据
```

## 最有用的产出：四档状态

不要二元的"完成/未完成"。用四档：

| 状态 | 含义 |
|---|---|
| ✅ 已验证 | 真实链路跑通，有证据 |
| 🟠 已实现未验证 | 代码在、有调用者，没跑过端到端 |
| 🔴 未实现 | 只有接口 / 空实现 |
| ⚪ 不适用 | 评估后决定不做 |

**关键在第二档。** 它让"我没骗你，但我也不敢打勾"变成一种体面的状态 —— 没有这一档，人只能被迫在撒谎和自认什么都没做之间选。

## 三类假货的快速判据

- **假数据**：问"这条数据是谁写进去的？" —— 答不上来就是假的
- **假实现（迁了骨架没接电）**：全仓 grep 调用点，零调用者 = 没接入
- **假实现（接入但没水源）**：从用户动作走一遍，每个参数的最初写入点在哪
- **假完成**：三样证据 —— 代码存在（最弱）/ 有调用者 / 跑通过（强），不全就不能打勾

## ⚠️ 边界

- 这是**审查与表达**技能，不替你补功能
- 四档状态要真的用起来，只写在文档里当装饰没有意义
- 有时候"明确说没做"比"含糊说做了"更需要勇气 —— 但这正是它存在的理由

```
帮我按真实性审一遍这次的交付，别放过假数据
```
