# Agent 编排

一个只会回答问题的模型，和一个助手，差四件事：**知道该谁答、记得住、说对话、知道下一步**。

## 一、四维治理（先定框架，再写流程）

任何业务分支都必须受这四维约束。**这是元框架，不是某个场景的规则。**

| 维 | 回答什么 | 失败长什么样 |
|---|---|---|
| **Goal** | 本次任务边界是什么，允许的输入来源有哪些 | 越界回答、拿外部知识冒充系统数据 |
| **Workflow** | 执行顺序：先取数 → 再检索 → 后推演 | 跳步、凭记忆答、先下结论再找证据 |
| **Output** | 输出给哪个终端，用哪种格式与语气 | 大屏里出现闲聊，对话框里甩一堆标签 |
| **Guard** | 绝对不能做什么 | 编数据、越权、给违规建议 |

**四维必须显式写出来。** 写在 prompt 里比写在人脑里可靠——人脑会在压力下省略。

### Workflow 的强制顺序

```
先工具取数 → 再知识检索 → 后逻辑推演
```

**不能跳步，不能盲猜。** 这条顺序是防幻觉最有效的一道闸：它让"没拿到数据"变成一个显式状态，而不是被模型用常识填坑。

## 二、路由决策树

### 设计原则

1. **第一层按输入形态分**，不是按话题分。图像 / 文本查询 / 开放式咨询——形态先决定走哪条流水线。
2. **每条分支写明"什么情况下不进入"**。排除条件比命中条件更重要。
3. **必须有兜底分支**，且兜底不是"我不懂"，是"降级到通用处理并说明降级"。

### 结构模板

```
输入
├─ 图像/视频类
│   ├─ 夜间/红外/安防语境 → 安防分支
│   ├─ 近景细节特写 → 诊断分支
│   └─ 常规场景画面 → 主判别分支
│        ├─ 步骤 1 粗筛（有没有目标）
│        ├─ 步骤 2 取业务上下文（对象是谁）
│        └─ 步骤 3 挂载对应技能
│             ├─ 已绑定具体对象 → 专用技能
│             ├─ 已知大类 → 大类技能
│             └─ 未知 → 通用技能（不允许跳过）
├─ 结构化数据查询 → 问数分支
└─ 开放式咨询 → 检索 + 时效校验
```

### 三条铁律

1. **粗筛先行。** 先判"画面里有没有目标"，再判"目标什么状态"。反了就会在空画面上硬推理。
2. **上下文优先于推断。** 能从系统取到对象身份，就不要靠画面猜。
3. **未知时降级，不放弃。** 走通用分支并注明"未绑定具体对象，按通用基准判读"，同时给一条数据治理建议。

## 三、三层记忆

| 层 | 存什么 | 生命周期 | 典型作用 |
|---|---|---|---|
| **短期** | 本次会话内的序列状态（帧 1 观察到 A，帧 2 观察到 B） | 单次分析 | 把离散观测串成演进过程 |
| **对话** | 最近 5–10 轮的指代上下文 | 单次会话 | 承接"那它呢""这周呢" |
| **长期** | 按租户/站点持久化的档案与历史汇总 | 跨天跨会话 | 对比、趋势、主动预警 |

### 三条纪律

1. **短期记忆不要落盘。** 它是推理的中间态，不是数据。
2. **对话记忆只保留指代，不保留结论。** 结论过期比丢失更危险。
3. **长期记忆必须带作用域键**（租户 / 基地 / 点位），**跨作用域读取是安全事故，不是 bug**。

### 指代继承

用户追问"那它这周呢"时，要能自动继承上一轮的**对象 + 时间范围**。

- 继承什么：对象身份、时间锚点、筛选条件
- 不继承什么：上一轮的结论、置信度、建议

## 四、双模式表达

同一事实，两种载体，两套措辞。

| 模式 | 场景 | 特征 |
|---|---|---|
| **A 严肃模式** | 大屏告警、工单、报告 | 客观克制、因果直白、动词明确、零废话 |
| **B 亲和模式** | 日常对话框、科普、非紧急提醒 | 口语化、委婉、可带一点幽默 |

### 翻译的是术语，不是事实

**模式 B 不许降低信息准确度，只许降低术语密度。**

| ❌ 术语直出 | ✅ 亲和版 |
|---|---|
| 昼夜垂直移动节律导致正午表层无个体 | 这对象跟人一样讲究作息，中午太阳毒它躲深处，早晚才出来 |
| 摄食强度已达饱食阈值，建议下调投喂速率 | 已经吃饱回撤了，再撒就不是喂，是请别人吃自助餐了 |

**红线**：亲和模式里**不许出现新的推断、不许改数量、不许软化风险等级**。幽默只能作用在修辞上。

### 模式切换的判据

不是"用户语气变了就切"，是**看载体**：
- 输出进结构化容器（卡片/告警框/报告）→ 模式 A
- 输出进对话气泡 → 模式 B
- 高风险事件 → **无论载体，强制模式 A**

## 五、预设问题引导

回答结束后，给 2–3 个**当前上下文下最可能想知道的下一步**。

好问题的三个特征：
1. 能用当前已有数据直接回答（不用用户再补条件）
2. 是自然的下一步，不是随机推荐
3. 指向一个有价值的动作（查、导出、排查、对比）

| 场景 | 引导示例 |
|---|---|
| 完成一次判别后 | 「要顺便查一下这个点位近 7 天的相关记录吗？」 |
| 触发异常后 | 「需要我整理一份该情况的排查清单吗？」 |
| 完成汇总后 | 「是否查看这段时间的异常汇总？」 |

**不要超过 3 个。** 超过就是菜单，不是建议。

## 六、常见失败与对应修法

| 症状 | 根因 | 修法 |
|---|---|---|
| 答错技能 | 第一层按话题分而非按输入形态分 | 改路由树第一层 |
| 多轮丢上下文 | 对话记忆没带指代键 | 追问时强制继承对象+时间 |
| 大屏里出现闲聊 | Output 维没定载体 | 按载体切模式，不是按语气 |
| 编造数据 | Workflow 允许跳步 | 强制"先取数后推演" |
| 每次都要用户重述条件 | 缺少长期记忆作用域 | 按租户/点位持久化 |

## 七、自检

- [ ] 四维（Goal/Workflow/Output/Guard）都显式写了
- [ ] 路由第一层按输入形态分，且每条分支有排除条件
- [ ] 有兜底分支，且兜底是降级不是拒答
- [ ] 三步记忆各有作用域和生命周期
- [ ] 追问能继承对象与时间
- [ ] 双模式翻译的是术语不是事实，高风险强制严肃
- [ ] 预设问题 2–3 个，且能直接用现有数据回答
