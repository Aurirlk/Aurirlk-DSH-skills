# agent-orchestration

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

多场景 Agent 总控编排：**路由、记忆、人设、引导**。

一个只会回答问题的模型，和一个助手，差四件事：**知道该谁答、记得住、说对话、知道下一步。**

## 什么时候用

- 设计一个需要多技能协同的 Agent
- 排查「答错技能」「多轮丢上下文」「告警话术太啰嗦」
- 同一套能力要同时服务结构化终端（大屏/卡片）和对话终端

## 四维治理（先定框架再写流程）

| 维 | 回答什么 | 失败长什么样 |
|---|---|---|
| **Goal** | 任务边界与允许的输入来源 | 拿外部知识冒充系统数据 |
| **Workflow** | 先取数 → 再检索 → 后推演 | 跳步、凭记忆答 |
| **Output** | 输出给哪个终端，用哪种格式语气 | 大屏里出现闲聊 |
| **Guard** | 绝对不能做什么 | 编数据、越权、违规建议 |

**四维要显式写出来**——写在 prompt 里比写在人脑里可靠，人脑会在压力下省略。

## 路由三条铁律

1. **粗筛先行**：先判"有没有目标"，再判"目标什么状态"。反了就会在空画面上硬推理。
2. **上下文优先于推断**：能取到对象身份，就不要靠画面猜。
3. **未知时降级，不放弃**：走通用分支 + 注明"未绑定具体对象"，并给一条治理建议。

**兜底分支不是"我不懂"，是"降级处理并说明降级"。**

## 三层记忆

| 层 | 存什么 | 生命周期 |
|---|---|---|
| 短期 | 本次会话内的状态序列 | 单次分析 |
| 对话 | 最近 5–10 轮指代上下文 | 单次会话 |
| 长期 | 按作用域持久化的档案与汇总 | 跨天 |

- **短期不落盘**：它是推理中间态，不是数据
- **对话只留指代，不留结论**：过期结论比丢失更危险
- **长期必须带作用域键**：跨作用域读取是安全事故，不是 bug

## 双模式表达

| 模式 | 场景 | 特征 |
|---|---|---|
| **A 严肃** | 大屏告警、工单、报告 | 客观克制、因果直白、动词明确 |
| **B 亲和** | 日常对话框、科普、非紧急 | 口语化、委婉、可带一点幽默 |

**翻译的是术语，不是事实。**

> ❌ 昼夜垂直移动节律导致正午表层无个体
> ✅ 这对象跟人一样讲究作息，中午太阳毒它躲深处，早晚才出来

**红线**：亲和模式不许出现新的推断、不许改数量、不许软化风险等级。幽默只能作用在修辞上。

**切换判据看载体，不看语气**；高风险事件无论载体一律模式 A。

## 预设问题引导

回答结束后给 2–3 个当前上下文下最可能想知道的下一步。

好问题三特征：能用现有数据直接回答 / 是自然下一步 / 指向有价值动作。

**不要超过 3 个——超过就是菜单，不是建议。**
