# 缓存迁移手册（NTFS Junction）

> 把写死在 C 盘的缓存目录搬到别的盘，**对应用程序完全透明**。

---

## 为什么用 Junction

很多软件的缓存路径是写死的或用注册表存的，改不动。Junction 的价值在于：

- **零配置**：不改任何软件设置，程序照常按老路径读写
- **不占额外空间**：Junction 本身只是文件系统里的一个重解析点
- **不需要管理员**：`mklink /J` 和 `New-Item -ItemType Junction` 普通权限即可（**符号链接 `mklink /D` 才需要管理员或开发者模式**）

## 什么时候不该用 Junction

**如果这个缓存路径本身可以用环境变量配置，优先改环境变量。** Junction 是"配置改不动"时的退路。

例如：
- 能改环境变量的：`PUPPETEER_CACHE_DIR`、`HF_HOME`、`NPM_CONFIG_CACHE`
- 改不动的：很多 GUI 软件把自己写死在 `%LOCALAPPDATA%\<厂商>\<产品>\Cache`

判断方法：

```powershell
# 这个目录有没有被环境变量指向？有 → 改环境变量去
Get-ChildItem env: | Where-Object { $_.Value -like '*<路径关键词>*' }
```

## 标准流程（`Move-Cache.ps1` 自动执行）

```
1. 校验      源存在 / 源不是已有链接 / 源与目标不同盘 / 目标盘空间够 / 源内无备份子目录
2. robocopy  源 → 目标（/E /COPY:DAT）
3. 校验      比对文件数与总字节数，不一致就中止（源不动）
4. 删源      只有校验通过才删
5. 建链接    New-Item -ItemType Junction -Path <源> -Target <目标>
6. 校验      确认 Junction 能正常读到内容
7. 记录      logs\junction-<时间戳>.json，供回退
```

**任何一步失败都中止，且源目录尽量保持不动。** 特别是第 3 步——**校验不通过绝不删源**，这是整个流程最关键的安全点。

## 用法

```powershell
# 预演（默认，不做任何改动）
.\Move-Cache.ps1 -Source "$env:USERPROFILE\.cache\puppeteer" -Destination "E:\Cache\puppeteer"

# 执行
.\Move-Cache.ps1 -Source "..." -Destination "..." -Execute

# 查看所有迁移
.\Move-Cache.ps1 -List

# 回退（删 Junction → 数据搬回 → 清理空目标目录）
.\Move-Cache.ps1 -Rollback -Manifest "logs\junction-20261004-221530.json"
```

## 必须知道的坑

### 1. 跨盘才有意义

源和目标在同一个盘（分区）上，迁移**不释放任何空间**，只是把数据挪了个位置。脚本会警告并要求 `-Force`。

### 2. 别把数据目录当缓存迁

迁移前脚本会检查源内三层内有没有 `backup` / `recover` / `备份` / `恢复` 子目录，有就阻断。理由见[垃圾分类判据](垃圾分类判据.md)里的真实案例——`WPS_Cache` 里就藏着文档恢复副本。

### 3. 程序在运行时不能迁

被占用的文件复制会失败或产生不一致。迁之前关掉相关程序。脚本的校验步骤能拦住不一致的情况，但最好一开始就避免。

### 4. 有些程序能识别出 Junction

极少数程序会检查路径是否为重解析点（例如某些安全软件、部分安装程序）。遇到过就直接回退。

### 5. 备份软件可能重复计算

某些备份工具会把 Junction 目标的内容也备份一遍，导致备份体积翻倍。如果用户用这类工具，迁移前要确认其排除规则。

### 6. 回退要趁早

`Move-Cache.ps1 -Rollback` 依赖 `logs\junction-*.json` 记录。**别删 logs 目录**，否则只能手动删链接再把数据搬回来。

### 7. 系统还原点/影子副本不含 Junction 目标

系统还原只保护卷内的实际数据，Junction 指向的其他卷内容不在还原范围内。

## 手工操作对照

`Move-Cache.ps1` 不可用时，手工三步：

```powershell
# 1. 复制（robocopy 比 Copy-Item 稳，能续传、能报告）
robocopy "C:\源目录" "E:\目标目录" /E /COPY:DAT /R:1 /W:1

# 2. 肉眼确认两边一致（文件数、总大小），再删源
(Get-ChildItem "C:\源目录" -Recurse -File | Measure-Object Length -Sum).Sum
(Get-ChildItem "E:\目标目录" -Recurse -File | Measure-Object Length -Sum).Sum
Remove-Item "C:\源目录" -Recurse -Force

# 3. 建 Junction
New-Item -ItemType Junction -Path "C:\源目录" -Target "E:\目标目录"
# 或命令行： mklink /J "C:\源目录" "E:\目标目录"
```

**检查链接是否有效**：

```powershell
(Get-Item "C:\源目录" -Force).LinkType    # 应显示 Junction
(Get-Item "C:\源目录" -Force).Target      # 应显示目标路径
```
