# 垃圾分类判据

> 本文是 `Find-Junk.ps1` 里分类规则的**人类可读版本**。改脚本前先看这里，改完记得同步。
>
> 安全等级：✅ Safe 可直接清 / ⚠️ Confirm 需人确认 / 📄 Report 只报告

---

## ✅ Safe 类：删了只会重建或本来就是垃圾

### `agent-residue` —— Agent 运行脚本残余

| 形态 | 路径 | 为什么安全 |
|---|---|---|
| npx 临时安装 | `%LOCALAPPDATA%\npm-cache\_npx`、`~\npm-cache\_npx`、`~\.npm\_npx`、`<node>\node_cache\_npx` | 每次 `npx -y <包>` 在这里解包一份，下次用到会重新下 |
| 会话中转产物 | `%TEMP%\dsh-spill-*`、`dsh-subprocess-*`、`dsh-workspace-changes-*`、`dsh-acl-skill-*` | DSH 单次会话的临时文件，会话结束即可清 |
| 工具临时目录 | `%TEMP%\claude`、`%TEMP%\opencode`、`%TEMP%\codex`、`~\.codex\.tmp`、`~\.claude\tmp` | 各 agent 的临时工作区 |

**⛔ 绝不能在同一个根目录下顺手删的东西**：`auth.json`（登录凭据）、`config.toml`、`sessions\`、`history\`。所以脚本只针对 `.tmp` / `tmp` / `_npx` 这类明确临时性的叶子目录，**不会整体删任何 agent 的根目录**。

### `crashdump`

- `%LOCALAPPDATA%\CrashDumps`
- `%LOCALAPPDATA%\Microsoft\Windows\WER\ReportArchive`、`ReportQueue`

程序崩溃转储与错误报告。排查完崩溃就无价值。

### `dev-cache`

| 工具 | 默认路径 | 清除后果 |
|---|---|---|
| uv | `%LOCALAPPDATA%\uv\cache` | 重新下载 |
| npm | `%LOCALAPPDATA%\npm-cache\_cacache` | 重新下载 |
| pip | `%LOCALAPPDATA%\pip\cache` | 重新下载（也可 `pip cache purge`） |
| Yarn | `%LOCALAPPDATA%\Yarn\Cache` | 重新下载 |
| Cargo | `~\.cargo\registry\cache` | 重新下载 |

### `build-cache`（需 `-ProjectRoots` 才扫）

`node_modules\.cache`、`.turbo`、`.next`、`.nuxt`、`.parcel-cache`、`.vite` —— 下次构建重建。

## ⚠️ Confirm 类：可能含数据或影响可感知

### `temp` —— 临时文件

`%TEMP%` 里的旧文件。

**为什么是 Confirm 而不是 Safe**：`%TEMP%` **就是环境变量 `TEMP` 指向的位置**。按时间只清里面的旧文件不破坏这个配置位置，但它终归是活跃目录，所以扫描器会自动把它降级为 Confirm（脚本里的 `EnvProtected` 逻辑）。

**实际执行时按"当下"重新判定过期**，不用计划生成时的旧结果——因为计划可能是几小时前生成的。

### `browser-cache`

Chrome / Edge / Brave 的 `Cache`、`Code Cache`、`GPUCache`、`Service Worker\CacheStorage`。

**这一类体积往往最大**（实测单机 Edge 的 CacheStorage 单项 3.25 GB、Chrome 合计 1.7 GB）。

- 会重建，但清完首次打开网站会变慢
- **必须先关掉浏览器**，否则文件被占用删不干净
- 用户若在线登录了某些服务，清 CacheStorage 可能要求重新登录

### `home-cache` —— `~/.cache/<工具>`

各工具约定俗成的本地缓存目录。**体积可能很大**（实测 `~/.cache/puppeteer` 583 MB 是 Chromium 二进制）。删了下次使用会重新下载。

### `recycle-bin`

各盘 `$RECYCLE.BIN`。**清空前必须确认里面没有还要恢复的文件。** 注意：回收站不清就不释放空间。

### `update-residue`

`C:\Windows\SoftwareDistribution\Download`。**需要管理员**，建议先停 `wuauserv` 服务。

## 📄 Report 类：只报告不清理

### `large-file`

`Downloads` / `Desktop` / `Documents` 里超过 `-LargeFileMB`（默认 1024 MB）的单个文件。**永远交给用户判断**——那是用户自己的数据。

## 安全层：脚本强制执行的拦截规则

在 `Add-Item`（扫描时）和 `Invoke-Cleanup`（执行时）**各执行一遍**：

| 规则 | 行为 |
|---|---|
| 目标是环境变量指向的路径 **且** 模式是 `WholeDir` | **拒绝**（整体删活跃配置位置 = 破坏环境） |
| 目标是环境变量指向的路径 **且** 模式是 `AgeFilter` | 允许，但**安全等级强制降为 Confirm** |
| 目标内部含 `backup`/`recover`/`restore`/`备份`/`恢复`/`autosave` 子目录 | **拒绝**，除非显式 `-Force` |
| `NeedsAdmin` 且当前非管理员 | **跳过**并提示 |
| 目标已不存在 | 跳过 |

**这个双层设计的意义**：即使计划文件是旧的、或者被篡改过，执行时仍然拦得住。实测把 `E:\Cache\codex`（含登录凭据）伪造成 Safe 项强行执行，被拒绝了。

## 真实案例：差点删掉的东西

| 时间 | 目标 | 发现了什么 | 教训 |
|---|---|---|---|
| 2026-10-03 | `E:\WPS_Cache`（3.3 GB） | 里面藏着 `Kingsoft\office6\backup`——82.8 MB、62 个文件的**文档崩溃恢复副本** | `*_Cache` 这种名字的目录里也可能有数据 |
| 2026-10-03 | `E:\Cache\huggingface`、`modelscope`、`puppeteer` | 分别是 `HF_DATASETS_CACHE`、`MODELSCOPE_CACHE`、`PUPPETEER_CACHE_DIR` 指向的目标 | 删缓存前先查环境变量 |
| 2026-10-03 | WPS / QQ音乐缓存 | 表面上"没开着"（没有可见窗口），实际有 4 个托盘进程占着 | `MainWindowTitle` 为空 ≠ 没在运行 |
| 2026-10-04 | 项目 `node_modules\.cache`（64.6 MB） | 属于在跑的项目 | 构建缓存要确认项目没在编译 |
