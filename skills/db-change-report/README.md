# db-change-report

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

库改动和代码改动不是一回事。代码推错了再推一次就行，**库改错了往往只能靠备份**。

这个技能管交付里那段最容易被糊过去的话 —— "另外我顺手改了张表"。

## 它要求什么

凡是动库（DDL / 数据 UPDATE / 建备份表 / 给运维一份待执行脚本），交付里必须有**单独一段报备**，答满五项：

| # | 必答 |
|---|---|
| 1 | 脚本文件名 + 类型（DDL / UPDATE / 备份表） |
| 2 | TEST 是否已执行，附证据 |
| 3 | PROD 待执行清单**与顺序** |
| 4 | 是否需重启 / 重建 jar |
| 5 | 备份与回滚方式 |

## 为什么"五、顺序"这两项最要命

**顺序有方向**，而且方向随改动类型反转：

- 加列 / 建表 → **先库后码**
- 删列 / 改语义 → **先码后库**（旧字节码读到已删列，服务直接崩）

**回滚要能落到语句**。「有备份」不是回滚方案 —— 得说清用哪张表、哪一列、什么条件。

## 附带的三条工程习惯

1. **脚本默认幂等**：`IF NOT EXISTS` / 信息模式判断 / 单一哨兵条件，复跑影响 0 行
2. **数据订正优先用历史表**，不新建 `*_bak_*`：改前落历史、改后回填、回滚 = 反向 UPDATE
3. **验证要有证据**：`SHOW CREATE TABLE` 逐字比对、关键字段 MD5、复跑 0 行

## ⚠️ 风险声明

这个技能会指导 agent **执行数据库变更**，属于高风险操作。

- 禁止从本机直连生产库写数据（除非你明确授权并当轮确认）
- `KILL` / `DROP` / `TRUNCATE` 必须单独确认，不能混在"顺手清理"里
- 生产写操作前必须有可用的回滚路径

## 用法

```
我要给这张表加两列，帮我把变更报备写全
```

```
这个脚本要在生产执行，帮我检查幂等性和回滚方式
```

模板和 SQL 写法见 [SKILL.md](SKILL.md)。

## 安装

```powershell
cd "$env:USERPROFILE\.dsh\profiles\desktop"
pnpm add github:Aurirlk/Aurirlk-DSH-skills
```

## 边界

- 只管**变更的表达与安全**，不替你判断业务上该不该改
- 幂等写法以 MySQL 8 为主；其它库的等价写法在 SKILL.md 里给了思路
- 真实执行仍需有权限的人来做，agent 不该拿着生产口令自行操作
