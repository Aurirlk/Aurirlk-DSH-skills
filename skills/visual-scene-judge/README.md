# visual-scene-judge

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

看监控画面，判断发生了什么。

**最大的坑不是看错，是没先说清自己能看见什么，就开始下结论。**

## 先说一个真实的麻烦

深夜，红外画面里有团暗影在动。

是有人在挣扎，还是风把水面吹皱了？

- 判"有人落水"——万一是波浪，半夜惊动救援队，第二天全组看你。
- 判"没事"——万一真有人，那不是闹笑话的事。

**同一个画面，两种判法，代价差几个数量级。**

这时候真正难的不是"你看到了什么"，而是**"这张图根本看不清那些"**。

这个技能干的第一件事，就是让你把这句话说出来。

## 第一步：先把看不清的说清楚

在给任何结论之前，先说这一句：

> 「本次依据是远距离俯视监控，看不清个体细节，以下结论只基于群体动线和水面扰动。」

说完这句，后面所有结论的可信度就自动被限定了。

**这是保护，不是免责。** 它让读的人知道该拿这个结论当多重的证据用。

要交代的有五样：

| 要说的 | 为什么要说 |
|---|---|
| 距离 | 远距离只能看群体，看不了个体 |
| 光照 | 夜间红外没有颜色，靠颜色判断的招全废 |
| 遮挡 | 反光、雨雾会让一部分区域根本判不了 |
| 帧率 | 抽帧间隔大，判不了瞬时动作，只能判趋势 |
| 分辨率 | 太模糊就判不了小细节，别硬判 |

## 第二步：四个互不相干的角度交叉看

只靠一个特征下结论，特别容易翻车。

**要四个互相独立的角度同时指向同一个答案，才下结论。**

| 角度 | 问什么 |
|---|---|
| **朝哪去** | 是朝一个中心聚拢，还是朝四周散开？ |
| **整不整齐** | 是同向列队，还是各走各的、有离群的？ |
| **变化快慢** | 是慢慢起、慢慢落，还是"啪"一下变了？ |
| **留下什么** | 投进去的东西消耗得快不快，有没有堆积？ |

**四个角度打架的时候怎么办？——如实说它们打架。**

不要投票，不要硬凑一个结论。

> 「朝向显示在主动靠近，但整齐度上出现了离群个体。两者矛盾，倾向判为局部异常，不是整体状态改变。」

**报告矛盾，比强行统一有用得多。**

## 第三步：看变化的速度和形状

单张图只能判"现在什么样"，**连着几张才能判"正在往哪走"**。

真正有用的判据不是数值大小，是**形状**：

| 形状 | 通常意味着 |
|---|---|
| 平滑地涨起来，再平滑落下去 | 正常开始、正常结束 |
| 突然没的（断崖） | 有外力介入 |
| 一直在高位不动（平台期太长） | 卡住了，不正常 |
| 反复起起落落 | 循环故障 |

**这一条几乎能搬到所有时序场景**——不限于监控。

## 第四步：给每个"容易看错"的情况配一个鉴别点

这是这个技能最实用的部分。

做法：把这类场景里最常被误判的情况列出来，每种写一行——

**「看起来像 X，但如果真是 Y，你会同时看到 Z。」**

| 表面现象 | 常被误判成 | 怎么区分 |
|---|---|---|
| 群体剧烈翻动 | 异常暴动 | 朝中心聚 = 正常高强度作业；朝四周散 = 受惊 |
| 表面很平静 | 空无一人 | 找有没有零星小扰动。**不热闹 ≠ 没有** |
| 动静突然没了 | 系统故障 | 看有没有外部输入变化。平滑下降多半是正常结束 |
| 有一小块异常 | 整体异常 | 看离群占比。低于 5% 多半是个体问题 |

**写鉴别点有个硬要求：它必须是能"看"出来的。**

「注意区分」不是鉴别点。**「看它是朝中心还是朝四周」才是。**

## 没有历史数据怎么办

很多场景你手上没有基准，也不知道"多少算多"。

这时候**不许自己编一个绝对阈值**：

| ❌ 编的 | ✅ 能验证的 |
|---|---|
| 「扰动高度超过 20cm 算高强度」 | 「跟这一段的起始帧比，扰动面积扩大了 3 倍以上」 |

用相对变化，有两条规矩：

1. **必须说清是跟什么比**（起始帧 / 这个点位的历史 / 隔壁时段）
2. **不许把倍数换算成具体物理量**（3 倍就是 3 倍，不要说"约 20 厘米"）

## 五条不准

1. 看不清就写"无法辨认"，不要脑补
2. 不许从一张图推断长时间趋势
3. **不许把"我没看到"写成"不存在"**——这两句话差一整个观测条件
4. 不许编编号、编时间、编数量
5. 结论必须能指回"图里哪一块"，指不回去就降低把握程度
