# nl2sql-analyst

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

用大白话查数据库。

**难的不是把话翻译成 SQL。难的是查对表、不串数据、说清口径、查不到别编。**

## 先说三个真实会出事的场面

**① 查出别人家的数据**

你在给 A 公司做问数。用户问「上个月的订单量」。

SQL 生成得挺漂亮，也跑通了。但 `WHERE` 里忘了加租户条件——

**结果把 B 公司、C 公司的订单一起算进去了。** 这不是 bug，这是安全事故。

**② 数字对得上，口径对不上**

用户问「转化率」，你算了 `feed / 增量`。数字出来了，2.8。

财务那边算是 1.4。

**两个人都没错，只是"转化率"这个词在系统里对应两张表。** 你取错了那张。

**③ 查不到，编了一个**

数据库里这个月没有记录。AI 一看空结果，顺手接了一句：

> 「本月转化率约 1.5，属于正常水平。」

**这句话是它编的。** 而且用户很可能就信了。

这三个场面，就是这个技能要堵的三个洞。

## 六步走

```
① 弄清问的是谁、哪段时间、哪个对象、要哪个数
② 把口语词换成表字段和算法
③ 生成 SQL（必须安全）
④ 查
⑤ 看结果对不对、异常就找原因
⑥ 选图
```

## 第一步：先把四件事问清楚

| 要问清 | 缺了会怎样 |
|---|---|
| **哪个租户 / 哪个基地** | 缺一个就是上面第①种事故 |
| **哪段时间** | "最近""这周"要换算成具体日期 |
| **哪个对象** | 具体点位还是全部汇总 |
| **要哪个指标** | 有歧义就列两个让用户挑 |

**时间一定要回显一次**：「2026-11-13 至 2026-11-19」。用户能在这个阶段纠正，比出了结果再吵架便宜得多。

## 第二步：把口语词翻译成表字段

这一步要同时写清三样：**从哪张表取、怎么算、以及不要从哪张表取**。

**第三样最容易被忽略，也最容易出事。**

因为你只说「日投喂量从 feeding_log 取」，模型还是可能去翻监控事件表——那张表里也有个叫 `feed` 的字段。

所以每个容易混的指标，都要写明禁忌：

| 用户说法 | 从哪取 | 怎么算 | **不要从哪取** |
|---|---|---|---|
| 日投喂量 | `feeding_log` | `SUM(feed_weight)` 按日聚合 | **不要从监控事件表取** |
| 转化率 | `feed_log` + `biomass` | `SUM(feed) / (期末-期初)` | 分母要为 0 时保护 |
| 达成率 | `target` + `actual` | `actual / target` | 目标没设置时直接说"无目标" |

## 第三步：SQL 四条安全线

### 1. 每张表都要带租户条件

**不只是主表。所有 `JOIN` 进来的表，`WHERE` 里都要有。**

```sql
WHERE t.tenant_id = :tenant_id
  AND t.base_id = :base_id   -- 上下文指定了才加
```

漏一张表，就是上面第①种事故。

### 2. 只准查，不准改

只允许 `SELECT`。`INSERT` / `UPDATE` / `DELETE` / `DROP` 一律不行。

**要拦在工具层，不能只写在提示词里。** 提示词是能被绕过的。

### 3. 除法一律加保护

```sql
SUM(a) / NULLIF(SUM(b), 0)
```

不加必炸，且不是每次都炸——**偶发故障比必现故障更烦人。**

### 4. 参数绑定，不要拼字符串

拼字符串就是在给注入开门。

## 第四步：查不到就直说

**这是最常被打破、也最不能容忍的一条。**

| ✅ 对 | ❌ 错 |
|---|---|
| 「当前条件下暂无记录，请核对编号，或确认数据是否已录入」 | 用"通常""一般""大约"编一个数 |

**空结果是数据，不是失败。** 它本身就在告诉你：要么条件错了，要么录入漏了。

顺便还能给一条更有用的建议：「这个点位近 3 天没有填报记录，建议排查录入流程。」

## 第五步：异常数字要解释，但只能基于查到的数据

查到数之后，如果明显不对劲（骤降、骤升、比率离谱），**不要只把数字丢给用户**。

要关联同期的环境数据解释：

```
指标：转化率 2.8（历史区间 1.2–1.6）
同期：平均温度 12°C（历史同期 22°C），投入量没减
解释：温度低导致效率下降，但投入没相应减少，所以比率升高
```

**但解释必须建立在查到的数据上。** 「可能是因为季节原因吧」这种不算解释，那是猜。

## 第六步：图表按数据形状选，不按好看选

| 数据长什么样 | 用什么图 |
|---|---|
| 一个指标随时间变 | 折线 |
| 多个对象横向比 | 分组柱状 |
| 两个指标、单位不同 | 双轴组合 |
| 占比构成（超过 6 类） | 堆叠柱 |
| 单个目标完成度 | 仪表盘 |

**图只是载体。结论要用一句话说清，而且这句话不能比数据更肯定。**
