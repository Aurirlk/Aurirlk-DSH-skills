**中文** | [English](README.en.md)

自然语言问数与指标归因。

**难点从来不是"生成 SQL"，是查对表、守边界、说清口径、查不到别编。**

## 什么时候用

用户用自然语言问业务数据，需要转成查询并解释结果：BI 问数、大屏取数、经营指标查询。

尤其适用于多租户系统、口径容易混、查不到数据时不能编的场景。

## 六步链路

```
①意图与上下文 → ②业务语义映射 → ③安全 SQL → ④执行 → ⑤校验与归因 → ⑥图表
```

## 安全四条铁律

| # | 规则 | 为什么 |
|---|---|---|
| 1 | 主表**与所有关联表**都注入作用域条件 | 漏一张就是跨租户泄露 |
| 2 | 只允许 `SELECT` | 写在工具层，不能只靠 prompt |
| 3 | 比率类加 `NULLIF(b, 0)` | 除零是必现故障 |
| 4 | 参数化，禁止拼接 | 注入 |

**跨租户查询是安全事故，不是 bug。这一条没有商量空间。**

## 语义映射要写"禁忌表"

光说"从哪里取"不够——**模型会就近找一张有相关字段的表**。

所以每个易混指标必须同时写：

| 说法 | 源表 | 口径 | **不要从哪取** |
|---|---|---|---|
| 日投喂量 | `feeding_log` | `SUM(feed_weight)` | **不从监控事件表取** |
| 转化率 | `feed_log` + `biomass` | `SUM(feed)/(end_b-start_b)` | 分母需保护 |

## 诚实原则

**空数据**：

- ✓「当前条件下暂无记录，请核对编号或确认数据是否已录入」
- ✗ 用"通常""一般""大约"编一个数

**这是最常被打破、也最不能容忍的一条。**

**异常波动**：不要只报数字，要关联同期环境变量做归因——但归因必须基于查到的数据，不能凭常识编。

## 图表按维度选，不按好看选

| 数据特征 | 图表 |
|---|---|
| 单指标时间趋势 | 折线 |
| 多对象横向对比 | 分组柱状 |
| 双指标关联（不同量纲） | 双轴组合 |
| 占比构成（>6 类） | 堆叠柱 |
| 单值达成 | 仪表盘 |

**图表只是载体。结论要用一句话说清，且这句话不能比数据更肯定。**
