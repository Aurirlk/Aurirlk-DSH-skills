# agent-tool-safety

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

给 agent 一把只读的铲子，最坏结果是查不到数据。
给它一把**能写库的**铲子，最坏结果是它一边道歉一边把生产改了。

这个技能管的是：**工具怎么设计，才能让模型既骗不了人，也骗不了自己。**

## 什么时候用

- 要给 agent 加会改东西的工具（改提示词、改配置、建智能体、跑脚本）
- 要设计「AI 提议 → 人确认 → 落库」的链路
- 要加总开关、只读模式、沙箱隔离
- 排查这几类事故：
  - 模型说"已为您更新"，实际只进了暂存区
  - 改 A 智能体，结果动了 B
  - 开关关了，模型还能调
  - 沙箱跑脚本一跑就 `exit=127`，或者中文全变方框

## 六条硬规则

1. **写工具一律 `draft_*`** —— 叫 `update_*`，模型必然宣称"已改好"
2. **草稿 ≠ 待批 ≠ 已生效** —— 分表，状态机明确，草稿不进待办列表
3. **变更必须带 `scope`** —— 两套自增序列会撞号，起草/查询/应用三处都要校验
4. **apply 只回写定向列** —— 先改状态再逐行处理，整行回写会把状态覆盖回去
5. **开关做在装配层** —— 关闭即不注册；框架的 EXPLORE 模式管不到自定义工具
6. **沙箱只读挂载、容器不连库** —— SQL 宿主执行，结果 CSV 挂进去

## 最反直觉的一条

> **框架的"只读模式"经常对自定义工具无效。**

实证过的机制：权限引擎签名写死某个基类，自定义实现直接 `return ALLOW`，根本不进检查。
所以"我把模式切成只读了"是假的 —— 唯一可靠的做法是**不注册**，让模型看不见。

## ⚠️ 风险声明

这个技能会指导 agent **设计有能力修改真实数据的工具**，属于高风险领域。

- 所有写路径必须有明确的确认层（人点确认，不是模型自己决定）
- 默认 `fail-closed`：不确定就关
- 沙箱挂载一律 `:ro`，除非明确需要写产物目录
- 绝不让容器直连生产库


## 安装

```powershell
cd "$env:USERPROFILE\.dsh\profiles\desktop"
pnpm add github:Aurirlk/Aurirlk-DSH-skills
```

## 边界

- 讲的是**安全边界与状态机**，不是某个 agent 框架的 API
- 沙箱部分以 Docker 为例，JVM/进程级隔离思路相同
- 不覆盖"模型该不该有这个能力"的产品判断 —— 那是你的决定，技能只保证做了就不会翻车
