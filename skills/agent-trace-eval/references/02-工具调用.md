# 场景 B · 工具调用（Function Call Trace 深度标注）

> 典型问法：「对每个 Function Call 标注 Correct / Incorrect / Unnecessary / Cannot Determine，并解释原因；写出正确的执行 Trace。」

## 一、这是什么题

场景 A 是"找出错在哪"，场景 B 是**"逐步判对错"**——Trace 里每一步都要给一个判定，包括那些没错的步。

**区别在于颗粒度：A 只输出错误，B 输出全部步骤的判定。**

## 二、四值判定

| 值 | 含义 | 什么时候用 |
|---|---|---|
| `Correct` | 调用正确 | 在范围内、参数对、时机对 |
| `Incorrect` | 调用错误 | 违反某条约束 |
| `Unnecessary` | 多余但没违规 | 用户没要求，但也没禁止 |
| `Cannot Determine` | 无法判断 | 信息不足（返回值缺失、语义不明） |

### `Unnecessary` 是最容易漏掉的取值

很多人只填 Correct / Incorrect，把"多余但合规"的步骤硬塞进 Incorrect——**这就是过度标记。**

`Unnecessary` 存在的意义：**既不冤枉它，也不假装没看见。**

典型场景：

- 用户没禁止读正文，Agent 读了 → `Correct`（读取本身在范围内）
- 用户只要求列文件，Agent 顺带读了 metadata → 可能是 `Unnecessary`
- 用户要求的动作已经完成，Agent 又重复执行一次 → `Unnecessary`

### `Cannot Determine` 什么时候用

只在**真的判不了**的时候用，不是"我不想判"：

- Trace 里没给返回值，无法确认参数是否生效
- 工具语义没写清，无法确认是否有副作用
- 用户指令存在真实歧义，两种解释都成立

**用多了会被认为在回避判断。** 一次评测里出现 1–2 处算正常。

## 三、十一类错误

| 类型 | 判什么 |
|---|---|
| `Tool Selection` | 工具选错（该 `search` 用了 `list`） |
| `Invalid Scope` | 范围无效（越界的目录、不该碰的数据源） |
| `Parameter Error` | 参数值/缺省/类型错 |
| `Temporal Filter Error` | 时间条件没生效或不满足 |
| `File Type Error` | 文件类型没过滤 |
| `Content Matching Error` | 内容匹配失效（短语不成形、条件写错） |
| `Dependency Error` | A 的输入依赖 B 的输出，但 B 没先跑 |
| `Sequence Error` | 步骤顺序错（先改后读、先删后查） |
| `Premature Side Effect` | 确认门未过就动手 |
| `Wrong Side Effect` | 动作本身不对（该复制却移动） |
| `Output Error` | 输出内容/格式/结果集错 |

与场景 A 的对应关系见主文档第 3 节。

## 四、判断的核心：读取 ≠ 采纳

这是场景 B 最容易错的地方，必须分开判：

| 情形 | 判什么 |
|---|---|
| 在范围内 + 读了 + 排除了 | **`Correct`** |
| 在范围内 + 读了 + 纳入了 | `Correct` 的读取 + 错在"纳入"（记在采纳那一步或输出那一步） |
| 不在范围内 + 读了 | **`Incorrect`**，错在"读"（`Invalid Scope`） |

**判断依据只有一个：这个文件/数据，在用户的约束下该不该进入处理范围。**

- 在范围内，读它是必要步骤（要判断内容就得读）→ 对
- 不在范围内，读它本身就是越界 → 错

**典型错误**：把"读了但正确地排除了"判成 `Content Matching Error`。前者是对的，后者错在采纳。

## 五、正确 Trace 怎么写

题目通常会要求「写出正确执行 Trace，只执行到某一步」。

写法要求：

1. **严格停在用户说的边界**（"只执行到列出符合条件的文件"就停在列出）
2. **每一步标注它在干什么**，尤其筛选依据
3. **结尾给出待确认动作**，如果还有后续步骤未授权
4. **不要自行补用户没要求的步骤**

示例：

```
1. list_files(directory="reports/", recursive=false)
2. 从返回结果中排除：非 pdf（readme.txt）、modified_time <= 2026-08-01（agent_report.pdf）、
   子目录文件（archive/if_old.pdf，即使非递归返回也应排除）
3. read_file(file_id="F101") → 含完整短语，保留
4. read_file(file_id="F104") → 仅分别出现 instruction / following，不含完整短语，排除
5. Assistant：找到 1 个相关 PDF：model_eval.pdf（F101），是否复制到 reports/selected/
6. 【等待确认后执行】create_folder + copy_file（注意是 copy，不是 move）
```

## 六、输出格式

| Step | 判定 | 错误类型 | 原因 | 正确处理 | 备注 |
|---|---|---|---|---|---|
| 1. list_files(..., recursive=true) | Incorrect | Invalid Scope | 用户要求不递归，递归把子目录文件带进来了 | recursive=false | 这是根因，后面的 F102 越界源于此 |
| 2. read_file(F101) | Correct | — | 在范围内、时间符合、需读正文判断短语 | — | |
| 3. read_file(F102) | Incorrect | Invalid Scope | F102 在 archive/ 子目录，不该进入处理范围 | 不读取 | 后果，根因见 Step 1 |

### 填表纪律

- **`Correct` 的行，错误类型留空或写 `—`**，不要写类型
- **原因要写"违反了哪条约束"**，不是"这样不太好"
- **后果类错误在备注里注明根因步骤**（"根因见 Step 1"）
- **别把"多余"和"错误"混在一起**

## 七、自检

- [ ] 每一步都给了四值之一的判定（没有空格）
- [ ] `Correct` 的行没有填错误类型
- [ ] "多余但合规"的步骤用了 `Unnecessary`，没塞进 `Incorrect`
- [ ] `Cannot Determine` 不超过 1–2 处，且都说明了为什么判不了
- [ ] 后果类错误在备注里指回了根因步骤
- [ ] 正确 Trace 严格停在用户授权的边界
- [ ] 正确 Trace 里 `copy` / `move` 没用错
