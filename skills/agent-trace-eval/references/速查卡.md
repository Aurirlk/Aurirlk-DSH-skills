## 三场景

| 场景 | 问法 | 输出 |
|---|---|---|
| **A 错误判断** | "哪里错了" | 错误清单（6 字段） |

## 五步（三场景通用）

```
1 读 Schema   → 必选/可选 · 参数形态 · 名不符实 · 返回值够不够 · 副作用
2 建台账     → C1…Cn，每条"可勾选的断言"
3 拆步骤     → S1…Sm
4 逐条对     → 只记有 C 支撑的
5 定级理由   → 三句话 + 可执行修正
```

## 「多余」怎么处理

| 场景 | 处理 |
|---|---|
| A | **不记** |
| B | 标 **`Unnecessary`** |

搞错就是过度标记。

## 四值判定（场景 B）

`Correct` · `Incorrect` · `Unnecessary` · `Cannot Determine`

- `Unnecessary`：多余但没违规
- `Cannot Determine`：信息不足，**一次评测最多 1–2 处**
- `Correct` 的行不填错误类型

## 严重度（场景 A / C）

```
不可撤销副作用？ → 能撤销? Major : Critical
结果内容错？     → Major
只是形式？       → Minor
只是没必要？     → 不记
```

一句话：**要不要回滚？**

## 八条铁律

1. **读取 ≠ 采纳**：范围内 + 读了 + 排除 = 对；纳入 = 错在"纳入"；范围外读了 = 错在"读"
2. **不必要 ≠ 违规**
3. **根因 ≠ 后果**：一条根因记一次
4. **报错 ≠ 静默成功**：后者更危险
5. **跑通 ≠ 用对**
6. **"不区分大小写"是放宽，不是跳过**
7. **包含 ≠ 开头**
8. **"确认后可做" ≠ "现在可以做"**

## 理由三句话

> ① 用户要求 **X**，Agent 做了 **Y**。
> ② 因为 **Z**，所以 **Critical/Major/Minor**。
> ③ 还触碰了 **C?**，次要不单列（或：独立错误另起 E2）。

## Rubric 六字段

`Rubric ID` · `Criterion` · `Judge Target` · `Type` · `Priority` · **`Expected Behavior`**

Judge Target：`Trace` / `Artifact` / `Final Answer` / `Workspace State` / `Multiple`

## GT 手算八步

```
数文件 → 数行 → 去重(全字段) → 过滤(<=) → 算比率 → 条件判断(>) → 排序+tie-break → 取前N
```

百分比分母是**全体**，不是总数。
