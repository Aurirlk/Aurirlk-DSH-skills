# 场景 C · 白盒测试（Rubric 设计与 Ground Truth）

> 典型问法：「Part A 设计 Rubrics；Part B 判断 PASS / FAIL 并列出所有失败项；Part C 计算 Ground Truth。」

## 一、这是什么题

场景 A 和 B 是判一个**已有标准**下的对错，场景 C 是**你自己定标准**，然后用这个标准判，再把正确答案算出来。

三部分缺一不可：

| Part | 产出 | 常见失分 |
|---|---|---|
| A | Rubric 表（六字段） | 标准写得太虚，不可判定 |
| B | PASS/FAIL + 失败项清单 | 只判错、没指根因 |
| C | Ground Truth 数值 | 手算错、边界符号错 |

## 二、Part A · Rubric 设计

### 六字段，缺一不可

| 字段 | 约束 | 失分点 |
|---|---|---|
| `Rubric ID` | `R01…`，与失败项编号一致 | 编号前空着或跳号 |
| `Criterion` | **必须可判定** | 写成"准确""正确"这类不可判的词 |
| `Judge Target` | `Trace` / `Artifact` / `Final Answer` / `Workspace State` / `Multiple` | 全填 Trace，不区分判什么 |
| `Type` | `Objective` / `Semi-objective` | Criterion 虚却标 Objective |
| `Priority` | `Must Have` / `Nice to Have` | 全标 Must Have |
| **`Expected Behavior`** | 写成"输入 X 时，输出必须是 Y" | **整列漏掉** |

### Criterion 的可判定标准

**换个判官会得出不同结论的，不合格。**

| ✗ 虚 | ✓ 实 |
|---|---|
| 合并数据的完整性和准确性 | 合并 a.csv 与 b.csv 共 9 行，不含 archive/c.csv 的数据 |
| AI 生成正确的报告 | 输出 6 列，顺序为 feedback_id/user_id/submitted_at/category/rating/comment |
| 筛选逻辑正确 | 使用 `rating <= 2`，筛出 5 条负面记录 |

**判据**：第三个人拿着这条，能独立判出对错。

写不出，就把 `Type` 降成 `Semi-objective`，并把 Expected Behavior 补具体。

### Judge Target 怎么选

| 值 | 判什么 | 例子 |
|---|---|---|
| `Trace` | 调用序列本身 | 是否递归、是否按顺序 |
| `Artifact` | 产出的文件/数据 | 输出文件的列数、行数、内容 |
| `Final Answer` | 最终回复文本 | 是否只含指定字段、有无多余评价 |
| `Workspace State` | 执行后的环境状态 | 原始文件是否被改动、目录是否被多建 |
| `Multiple` | 以上多项 | 跨层约束，比如"先判断再建目录" |

### 必须覆盖的七类

题目会要求覆盖：输入 Scope / Function Call / 数据处理逻辑 / Artifact 正确性 / Side Effect / 条件工作流 / 最终回复。

**建完后对照这份清单点数**，缺哪类补哪类。

## 三、Part B · 判定

### 整体判定

`PASS` / `FAIL` 是二值的，**只要有一个 Must Have 失败就是 FAIL**。

### 失败项清单

每条写四列：

| 列 | 写什么 |
|---|---|
| 失败项 | `R01`，与 Rubric ID 对应 |
| Agent 行为 | Trace 里的原始调用或输出 |
| 违反点 | 违反了哪条 Criterion 的哪一句 |
| 正确逻辑 | 应该怎么做 |

### 两个必须做到的

1. **说清根因与后果。** 后面几条失败往往源于第一条，要注明（"根因见 R01"）。
2. **编号连续。** 如果某个 Rubric 没失败，要么不列，要么说明它通过了——**不能跳号不留解释**。

## 四、Part C · Ground Truth 计算

这是全题唯一要求**你自己算出正确答案**的部分。**手算，别估。**

### 八步顺序（固定）

```
1. 数文件     → 注意"一级目录"和文件格式过滤
2. 数行       → 去重前总数
3. 去重       → 只删"指定字段完全一致"的行，其它一律不删
4. 过滤       → 注意边界符号（<= / <）
5. 算比率     → 分子分母分别是什么，题目写了就照抄
6. 条件判断   → > 还是 >=
7. 排序       → 降序 + 并列时的 tie-break（通常是字母序升序）
8. 取前 N     → 百分比的分母是"全体"，不是"总数"
```

### 手算纪律

- **每一步把中间数字写在纸上**，录屏时这张纸就是讲解稿
- **每个数字都能追溯到具体行**，别只写结果
- **边界符号抄下来再算**，不要心算

### 常见坑

| 坑 | 后果 |
|---|---|
| 递归进了子目录 | 文件数和行数全错 |
| 按单一字段去重 | 把同一用户的多条不同反馈删掉了 |
| `<=` 写成 `<` | 少算一批 |
| 比率分母用去重前 | 比率偏小 |
| 无 tie-break | 前 N 排序错 |
| 百分比分母用总数 | 占比全错 |

## 五、输出示例

### Part A

| Rubric ID | Criterion | Judge Target | Type | Priority | Expected Behavior |
|---|---|---|---|---|---|
| R01 | 只处理一级目录，不递归 | Trace | Objective | Must Have | 调用 `list_files(..., recursive=false)`，返回结果不含子目录文件 |
| R02 | 只处理 .csv 文件 | Trace | Objective | Must Have | 读入的文件集合为 {a.csv, b.csv}，不含 .json 与子目录文件 |
| R03 | 去重只删六字段完全一致的行 | Artifact | Objective | Must Have | 去重后 8 行；U01 的两条不同反馈均保留 |

### Part C

| GT 项目 | 正确答案 | 计算/依据 |
|---|---|---|
| 原始文件数 | 2 | 一级目录下 a.csv、b.csv；排除子目录 c.csv 与 readme.json |
| 去重前条数 | 9 | a.csv 4 行 + b.csv 5 行 |
| 去重后条数 | 8 | 仅 1 行六字段完全一致 |
| 负面反馈数 | 5 | `rating <= 2` |
| negative_ratio | 62.5% | 5 / 8 |
| 是否生成 summary | 是 | 62.5% > 20% |
