# 系统化根因诊断（RCA）

同一堆材料，可以写成一段猜测，也可以写成一份诊断。差别不在信息量，**在顺序**。

```
① 事实提取 → ② 假设与排他 → ③ 根因溯源 → ④ 分级处置与长效防御
```

## 0. 铁律（先于一切）

> **未完成事实提取与归因推导前，严禁给出任何处理或修复建议。**

跳步诊断是所有误判的第一来源。人一旦先想到"可能是 X"，后面看到的每个证据都会往 X 上靠。**先证据后结论不是流程洁癖，是对抗确认偏误的唯一办法。**

第二条铁律：

> **证据不足时，阻断流程并向用户索要特定维度的补充信息，而不是用推测填坑。**

## 1. 阶段一 · 事实提取（纯描述，零推断）

### 1.1 全量扫描

把手里所有材料过一遍：截图/视频/日志/参数/代码/对话历史。**不要只看出问题的那一块。**

### 1.2 分离现象与猜测

这一条决定整份诊断的成色。

| ✗ 混写 | ✓ 分开写 |
|---|---|
| 「接口超时说明数据库挂了」 | 现象：接口 P99 从 80ms 升到 3200ms；推断：下游依赖异常（置信度：中） |

**现象必须是可验证的**：在哪一层、什么时间、什么数值、偏离了多少、和什么对比。

### 1.3 建立假设池

列出 **1–3 个**疑似方向，各标置信度。

- **给一个 = 赌**
- **给十个 = 没给**

## 2. 阶段二 · 假设与排他

这是整份协议里最被低估的一段，也是它区别于普通"分析"的地方。

### 2.1 区分直接原因与系统性诱因

| 层 | 回答什么 | 例 |
|---|---|---|
| **直接原因** | 直接引爆当前表象的动作或状态 | 某个连接池被打满 |
| **系统性诱因** | 为什么这个条件有机会出现 | 缺少连接池上限告警、压测没覆盖并发峰值 |

**只写到直接原因 = 解释得了"这次为什么"，解释不了"为什么老是这次"。**

### 2.2 必须给出「低成本鉴别动作」

当有两个以上疑似方向、且现有证据无法二选一时，**不许含糊地说"考虑 A 或 B"**。

**必须给一个可执行、成本极低、结果能二选一的动作。**

| ✗ 含糊 | ✓ 可鉴别 |
|---|---|
| 「可能是缓存问题也可能是 DB 问题」 | 「把缓存开关关掉重跑一次：仍然慢 → 排除缓存」 |
| 「可能是网络也可能是应用」 | 「同机房 curl 直连：快 → 排除网络」 |
| 「可能是文档写得不清」 | 「让一个没参与的人只看文档复述流程：卡在哪一步 → 那就是缺失处」 |

**鉴别动作的三个要求**：能自己做、5 分钟内、结果是二值的。

### 2.3 排他表

| 假设 | 支持证据 | 反对证据 | 置信度 | 鉴别动作 |
|---|---|---|---|---|
| A | …… | …… | 高 | —— |
| B | …… | …… | 中 | 关缓存重跑 |

**"反对证据"这一列不能空着。** 空着说明你只是在找支持自己的东西。

## 3. 阶段三 · 根因溯源

### 3.1 下潜到底，写成因果链

```
触发条件 → 直接原因 → 为什么允许发生 → 为什么没被发现
```

**第四问最容易被跳过，也最值钱。** 一个问题能造成损失，往往不是因为发生了，而是因为**没有被及时发现**。

### 3.2 根因的判定标准

一个结论要算"根因"，必须满足：

- **可控**：有人能对它做出改变
- **可验证**：能设计一个实验证伪
- **可解释全部现象**：不能只解释一部分

不满足就还是"原因之一"，不是根因。

## 4. 阶段四 · 分级处置与长效防御

### 4.1 三级动作

| 级 | 目标 | 要求 |
|---|---|---|
| **① 应急止损（治标）** | 阻断损失扩大 | 立刻能做、成本最低、**尽量可逆** |
| **② 根治修复（治本）** | 消除阶段三锁定的根因 | 分步骤、有完成判据 |
| **③ 长效防御（防复发）** | 让它不再发生或不再无声发生 | 环境 / 监控 / 流程 三个维度 |

### 4.2 长效防御的三条硬要求

1. **改成机制，不是提醒人。** 「加强注意」「提高意识」等于没写。
2. **三条至少覆盖两条。** 只有监控没有流程，下次换个路径照样中。
3. **可验证。** 每条都能回答"怎么知道它生效了"。

### 4.3 高风险操作必须前置警告

若处置步骤涉及**不可逆操作**（删数据、改配置、重启生产、发版回滚），**必须在方案最前面用醒目警告标出**，并给出回滚路径。

> ⚠️ **风险**：以下操作不可逆。执行前先备份 `xxx`；回滚方式：`yyy`。

## 5. 熔断机制：什么时候必须停下来

出现以下情况，**停止输出处置方案，改为索要证据**：

| 情况 | 怎么做 |
|---|---|
| 关键视角/信息缺失 | 明确指出缺哪个，而不是猜一个 |
| 两种假设都说得通 | 给出鉴别动作，等结果 |
| 证据相互矛盾 | 报告矛盾，不强行统一 |
| 风险超出你可判断的范围 | 说明边界，建议找谁 |

**熔断话术模板**：

> 「当前信息只能确认 ____，无法区分 ____ 和 ____。请补充 ____（具体到可执行的采集动作），我可以给出确定结论。在此之前，建议先执行 ____（无风险的临时动作）。」

**注意最后半句**：熔断不等于甩手，要给出一个**零风险的临时动作**。

## 6. 输出模板

```markdown
## 一、现象与初步定性
- **客观观察**：（仅陈述可验证的事实，标注数据来源与时间）
- **疑似方向**：
  1. ____（置信度：高）—— 匹配特征：____
  2. ____（置信度：低）—— 缺证据：____

## 二、原因剖析
- **直接原因**：____
- **系统性诱因**：____
- **鉴别动作**（存在多解时）：____

## 三、处置与预防
- **① 应急止损**：____（完成判据：____）
- **② 根治修复**：____
- **③ 长效防御**：
  - 环境：____
  - 监控：____
  - 流程：____
```

## 8. 自检

- [ ] 现象与推断分开写，现象可验证
- [ ] 假设 1–3 个，各带置信度
- [ ] 排他表有「反对证据」列，且没空着
- [ ] 存在多解时给了可执行的鉴别动作
- [ ] 根因满足"可控 / 可验证 / 解释全部现象"
- [ ] 因果链写到了"为什么没被发现"
- [ ] 长效防御是机制而非提醒，且覆盖至少两个维度
- [ ] 高风险操作有前置警告与回滚路径
- [ ] 证据不足时走了熔断，没有编造
