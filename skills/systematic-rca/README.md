# systematic-rca

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

系统化根因诊断：**事实提取 → 假设与排他 → 根因溯源 → 分级处置与长效防御**。

同一堆材料，可以写成一段猜测，也可以写成一份诊断。差别不在信息量，**在顺序**。

## 核心铁律

> **未完成事实提取与归因推导前，严禁给出任何处理或修复建议。**

人一旦先想到"可能是 X"，后面看到的每个证据都会往 X 上靠。先证据后结论不是流程洁癖，是**对抗确认偏误的唯一办法**。

第二条：**证据不足时阻断流程并索要特定维度的补充，而不是用推测填坑。**

## 四阶段

| 阶段 | 强制动作 | 失败长什么样 |
|---|---|---|
| **① 事实提取** | 全量扫描 → 现象与猜测分列 → 1–3 个假设带置信度 | 现象和推断混在一起写 |
| **② 假设与排他** | 区分直接原因与系统诱因 → **给出低成本鉴别动作** | 含糊地说"可能是 A 或 B" |
| **③ 根因溯源** | 因果链下潜四问 | 只写到直接原因 |
| **④ 处置与防御** | 止损 / 根治 / 长效 三级 | 长效写成"以后注意" |

## 最被低估的一段：鉴别动作

有两个疑似方向但证据无法二选一时，**不许含糊**。

**必须给一个可执行、5 分钟内、结果二值的动作。**

| ✗ 含糊 | ✓ 可鉴别 |
|---|---|
| 「可能是缓存也可能是 DB」 | 「关掉缓存重跑：仍然慢 → 排除缓存」 |
| 「可能是网络也可能是应用」 | 「同机房直连 curl：快 → 排除网络」 |
| 「可能是文档不清」 | 「让没参与的人只看文档复述：卡在哪 → 那就是缺失处」 |

**鉴别动作的三个要求**：能自己做、5 分钟内、结果二值。

## 排他表

| 假设 | 支持证据 | **反对证据** | 置信度 | 鉴别动作 |
|---|---|---|---|---|
| A | …… | …… | 高 | — |

**「反对证据」不能空着。** 空着说明你只是在找支持自己的东西。

## 根因的判定标准

一个结论要算根因，必须同时满足：

- **可控**：有人能改变它
- **可验证**：能设计实验证伪
- **解释全部**：不能只解释一部分

## 长效防御三条硬要求

1. **改成机制，不是提醒人**——「加强注意」等于没写
2. **环境 / 监控 / 流程 至少覆盖两条**
3. **可验证**——能回答"怎么知道它生效了"

## 熔断

关键信息缺失、两假设都说得通、证据矛盾、风险超出判断范围时：**停止出方案，改为索要证据。**

> 「当前信息只能确认 ____，无法区分 ____ 和 ____。请补充 ____。在此之前建议先执行 ____（无风险临时动作）。」

**熔断不等于甩手**——要给一个零风险的临时动作。
