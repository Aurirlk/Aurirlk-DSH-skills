# systematic-rca

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

查问题查不准，大多不是因为不够聪明，**是因为顺序反了**。

## 先说一个你一定遇到过的场面

线上报错。你打开日志看了两眼，脑子里蹦出「应该是缓存没刷」。

然后你开始找证据——找到三条支持缓存的，更有把握了。

改完，还是报错。

再查了半天，发现是连接池被打满了。**前面那两个小时，其实都在给第一个念头找理由。**

这跟能力没关系。人一旦有了假设，眼睛就自动只看得见支持它的东西。

这个技能要做的，就是把顺序拧回来。

## 顺序是这样的

```
① 先看清发生了什么    ② 再列出几种可能
③ 想办法一条条排除     ④ 最后才动手
```

**中间那两步不能省，尤其④不能提前。**

## 第一条规矩：先看清，再动手

> **事实没理清、原因没推出来之前，不给任何修复建议。**

这条听起来像废话，但它是最容易被破坏的一条——因为客户在催、老板在问，你很想赶紧说点什么。

所以还有第二条：

> **证据不够，就停下来要。不要用「应该」「可能」把坑填上。**

停下来不丢人。猜一个然后修错，才丢人。

## 四步分别做什么

### 第一步：把看到的和想到的分开

这是整份诊断的分水岭。

| 这样就废了 | 这样就对了 |
|---|---|
| 「接口超时说明数据库挂了」 | 现象：接口 P99 从 80ms 涨到 3200ms<br>推断：下游依赖异常（把握：中） |

**现象要能被别人复核**：哪一层、什么时候、差了多少、跟什么比。

然后列出 **1 到 3 种**可能，每种标一个把握程度。

- 只列一种 = 在赌
- 列十种 = 等于没列

### 第二步：想办法把它们分开

**这一步是这个技能最值钱的地方，也是最容易被跳过的地方。**

两种可能都说得通、手上的证据分不开时，最常见的做法是：

> 「可能是缓存问题，也可能是数据库问题。」

**这是耍流氓。** 对方拿这句话什么都干不了。

正确的做法是给一个动作：

> 「把缓存开关关掉重跑一次。还是一样慢 → 排除缓存。」

**一个好的验证动作要满足三条**：自己能做、五分钟内、结果是二选一。

再来几个例子：

| 分不清 | 一个动作就能分开 |
|---|---|
| 缓存还是数据库 | 关缓存重跑：还慢 → 不是缓存 |
| 网络还是应用 | 同机房直连 curl：快 → 不是网络 |
| 代码问题还是环境问题 | 本地最小复现：能复现 → 代码；不能 → 环境 |
| 文档写得看不懂 | 让一个没参与的人只看文档复述：卡在哪 → 那就是缺的那块 |

### 第三步：挖到底

**一个原因要算"根因"，得过三关：**

| 关卡 | 问什么 |
|---|---|
| 有人能改吗 | 改不了的不叫根因，叫命 |
| 能验证吗 | 说得出怎么证伪 |
| 能解释全部吗 | 只解释一半的，是原因之一 |

然后顺着链条往下问四句：

```
是什么触发了它？
→ 为什么允许它被触发？
→ 为什么测试没拦住？
→ 为什么上线后没能及时发现？
```

**第三、第四句最容易跳过，也最值钱。**

只答第一句 → 修了一个地方。
答到第三句 → 补了一类测试。
答到第四句 → 改了发布流程。

### 第四步：分三档处理

| 档 | 干什么 | 要求 |
|---|---|---|
| **急** | 先止血 | 立刻能做、成本最低、尽量能撤回 |
| **治** | 消掉第三步找到的原因 | 分步骤、做完有验收 |
| **防** | 下次别再这样 | 改机制，不是提醒人 |

## 关于"防"，有一条硬标准

**「加强注意」「提高意识」等于没写。**

真东西长这样：

| 维度 | 例子 |
|---|---|
| 环境 | 版本锁定、配置校验、依赖锁文件 |
| 监控 | 关键路径打点、错误率告警、慢查询阈值 |
| 流程 | CI 门禁、灰度发布、review 清单 |

**三个里至少覆盖两个。** 只有监控没有流程，下次换个入口照样中；只有流程没有监控，出了问题还是靠用户来报。

## 分不清的时候怎么办

**停下来，说要什么。** 但要留一个应急动作。

> 「现在能确认 ____，但分不开 ____ 和 ____。麻烦你做一下 ____（具体怎么采）。在此之前，建议先 ____（零风险的动作）。」

**只停不给动作，是甩手。停下来还给了一条退路，才叫负责。**

## 四种场景，各有各的门道

| 场景 | 这个领域里"证据"指什么 | 点进去看 |
|---|---|---|
| 写代码、测代码 | 代码事实、跑出来的结果、测试输出 | [代码开发测试](references/01-代码开发测试.md) |
| 写文档、做视频 | 手头素材、读者反馈、他们卡在哪 | [文档与视频](references/02-文档与视频.md) |
| 事情是怎么发生的 | 时间线、日志、各人说法 | [事件溯源](references/03-事件溯源.md) |
| 回复别人报的 bug | 复现步骤、环境、现象记录 | [Bug 根因回复](references/04-Bug根因回复.md) |

每篇都写了：这个领域最要紧的一条原则、四步具体怎么走、最容易错在哪、以及一段能直接抄的示例。
