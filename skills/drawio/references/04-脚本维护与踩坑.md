# 脚本维护与踩坑

这个技能用的是 **Windows PowerShell 5.1**（不是 pwsh 7）。PS 5.1 有几个**不报错、只给你错结果**
的行为，下面几条都是写这几个脚本时真踩过的，改动脚本前请先读。

## 坑 1：`@()` 包在 `List[object]` 上会抛异常

```powershell
$list = New-Object System.Collections.Generic.List[object]
$list.Add([pscustomobject]@{ A = 1 })

@($list)          # ✗ 抛「参数类型不匹配」ArgumentException
@($list).Count    # ✗ 同上
$list.ToArray()   # ✓ 用这个
$list.Count       # ✓ List 自己的 Count 是好的
```

**连空 List 都炸**，而且炸在运行时——语法检查过不了这一关。所以静态检查脚本时，
重点看有没有 `@($变量)` 这种写法。

注意区别：`@($变量 | Where-Object { ... })` 是**安全的**，因为管道会把 List 拆开。
**出问题的只有 `@()` 直接包一个 List 变量。**

## 坑 2：函数返回 `List` 会被拆成裸对象，单元素时 `.Count` 是空

这是坑 1 的兄弟，也是**更难查**的一个。

```powershell
function Get-Things {
    $out = New-Object System.Collections.Generic.List[object]
    $out.Add([pscustomobject]@{ Index = 1 })
    return $out
}

$things = Get-Things          # ✗ 拿到的是裸的 PSCustomObject，不是数组
$things.Count                # ✗ 空！（不是 1）
$count = $things.Count
$r = 1..$count                # ✗ 1..$null 在 PowerShell 里等于 1,0（降序两元素！）

$things = @(Get-Things)       # ✓ 必须这样
$things.Count                # ✓ 1
```

**为什么难查**：多元素时 PowerShell 把 List 拆成 `Object[]`，`.Count` 正常，
代码看起来完全没问题；**只有恰好一个元素时才暴露**。本项目就在这个坑上栽过一次——
单页 `.drawio` 导出报出「页号超出范围：1,0」，而两页文件一切正常。

两处防线：

1. 调用方一律写 `@(函数调用)`——`@()` 包在**函数结果**上是安全的（那时它已经不是 List 了）
2. 拿到计数后立刻校验 `if ($count -lt 1) { ... }`，别让无效值流到 `1..$count` 里

## 坑 3：`.ps1` 必须有 UTF-8 BOM，`SKILL.md` 必须没有

PS 5.1 读**无 BOM 的 UTF-8** 文件时按 ANSI(GBK) 解释，中文全变乱码、脚本直接解析失败。
两个方向相反，极易弄反：

| 文件 | BOM |
|---|---|
| `*.ps1` | **必须有** |
| `SKILL.md` | **必须没有**（带 BOM 会让 frontmatter 的 `startsWith('---')` 失效） |

**编辑工具会剥掉 BOM。每次用编辑工具改完 `.ps1`，都要跑一遍：**

```powershell
..\..\scripts\Fix-Bom.ps1
..\..\scripts\Fix-Bom.ps1 -Check     # 只检查，有问题退出码 1
```

本项目开发过程中这个坑犯了四次，所以做成了脚本。

## 坑 4：`Start-Process -ArgumentList` 要自己加引号

`Start-Process` 对含空格的参数处理很差。`D:\Program Files\Draw.io\draw.io.exe`
当 `-FilePath` 没问题，但**传给它的参数**如果含空格就会被拆错。`Export-Drawio.ps1`
里的 `Quote-Arg` 就是干这个的：

```powershell
function Quote-Arg {
    param([string]$A)
    if ($A -match '[\s"]') { return '"' + ($A -replace '"', '\"') + '"' }
    return $A
}
$argStr = (($argList | ForEach-Object { Quote-Arg $_ }) -join ' ')
Start-Process -FilePath $Exe -ArgumentList $argStr -Wait -PassThru -WindowStyle Hidden
```

## 坑 5：测试产物不要写进仓库

导出会生成 PNG/SVG，体检会产生临时文件。**一律写到 `$env:TEMP`**，
否则 `git status` 会被产物刷屏，而且可能被 npm 打包发出去。

```powershell
$tmp = Join-Path $env:TEMP 'drawio-skill-test'
```

## 坑 6：解析 XML 时属性取不到值会静默变 0

`$geo.GetAttribute('x')` 在属性缺失时返回**空字符串**，`[double]''` 会抛异常。
所以脚本里有 `ToD` 这个辅助函数，空值走默认值：

```powershell
function ToD {
    param($V, [double]$Default = 0)
    if ($null -eq $V) { return $Default }
    $s = [string]$V
    if ($s -eq '') { return $Default }
    $r = 0.0
    if ([double]::TryParse($s, [ref]$r)) { return $r }
    return $Default
}
```

## 坑 7：`Write-Host` 的输出用 `2>&1` 抓不到

`Write-Host` 写的是**信息流**（stream 6），不是标准输出、也不是错误流。所以：

```powershell
$t1 = (& .\Export-Drawio.ps1 -Path x.drawio -ListPages 2>&1 | Out-String)
$t1.Length        # 0 —— 什么都没抓到！
$t2 = (& .\Export-Drawio.ps1 -Path x.drawio -ListPages *>&1 | Out-String)
$t2.Length        # 356 —— 这才是对的
```

要在测试里断言 `Write-Host` 的输出，必须用 `*>&1`（合并所有流）或 `6>&1`。

这个坑会**假装检查通过**——如果你的断言写成「输出里必须包含 X」，抓到空字符串时
`-notmatch` 会成立，检查照样报错；但如果写成「输出里不能包含 Y」，抓不到东西就永远通过，
**测试静默失效**。所以断言要挑「必须存在」的正向条件。

## 坑 8：压缩格式的 `.drawio`

draw.io 保存时可能把 `mxGraphModel` 压缩成 base64。此时 `<diagram>` 里**没有**
`mxGraphModel` 子节点，直接 `SelectNodes('.//mxCell')` 会一个都找不到——**不报错，静默返回空**。

判据和修法：

```powershell
$isCompressed = -not ($diagramNode.SelectSingleNode('mxGraphModel'))
```

解码是 **base64 → raw deflate → URL 解码**：

```powershell
$bytes = [Convert]::FromBase64String(($text -replace '\s',''))
$ms = New-Object System.IO.MemoryStream
$ms.Write($bytes, 0, $bytes.Length); $ms.Position = 0
$ds = New-Object System.IO.Compression.DeflateStream($ms, [System.IO.Compression.CompressionMode]::Decompress)
$sr = New-Object System.IO.StreamReader($ds, [System.Text.Encoding]::UTF8)
$xmlText = [System.Uri]::UnescapeDataString($sr.ReadToEnd())
```

`Test-DrawioLayout.ps1` 会自动处理；`New-Drawio.ps1` 生成的一律是未压缩格式。

## 改完脚本的检查清单

```powershell
# 1. BOM
..\..\scripts\Fix-Bom.ps1 -Check

# 2. 生成 → 体检 → 导出，整条链路跑一遍
$tmp = Join-Path $env:TEMP 'drawio-check'
.\New-Drawio.ps1 -Spec .\examples\sample-architecture.json -Out "$tmp\s.drawio" -Force -ThenTest
.\Export-Drawio.ps1 -Path "$tmp\s.drawio" -OutDir "$tmp\out"

# 3. 单页与多页都要试 —— 坑 2 只在单页暴露
.\Export-Drawio.ps1 -Path "$tmp\s.drawio" -ListPages
.\.Export-Drawio.ps1 -Path <一个两页的.drawio> -ListPages
```

**第 3 步不能省。** 单元素边界是这个技能里最容易复发的问题。
