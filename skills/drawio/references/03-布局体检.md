# 布局体检：四类缺陷

图能打开 ≠ 图能看懂。下面四类缺陷**不会让文件出错**，只会让图变成废话，
而且**只看 XML 很难发现**——必须把坐标算一遍才知道。

`scripts/Test-DrawioLayout.ps1` 就是干这个的：读 `.drawio`，按几何算出这四类问题并点名。

## 为什么需要自动检查

人眼的三个失效场景：

1. **缩略图尺度**：差 3 个像素的越界，在 20% 缩放下完全看不见
2. **密集区域**：一屏几十个方框时，两个框重叠反而像是「一组」
3. **连线**：正交连线横穿中间方框时，看起来像是「连线本来就该这样」

这三种都有一个共同点：**在最终出图之前，没有任何东西会报错。**

## 缺陷 1：方框重叠

两个形状的矩形相交（超过容差）。

**成因**：手算坐标。同一行放 5 个 185 宽的方框，间距算错 1 个就往回压。

```powershell
# 185 宽 × 5 个，起点 190，间距 210 → 最后一个右边界 1215，正好不出界
x = 190, 400, 610, 820, 1030
```

**修法**：

- 用 `New-Drawio.ps1` 的自动布局，它按容器宽度等分，从数学上排除重叠
- 手写的话，用「左边界累加」而不是「中心点 ± 半宽」——后者会累积舍入误差
- 保证 `间距 >= 宽度`，别用 `宽度 + 5` 这种贴边值

**什么不算重叠**：

- `text;` 纯文字标签（标题、层名）压在别的东西上——这是设计意图
- 分层容器和它里面的方框——父子关系
- 刻意叠放的装饰层（比如深色顶栏压在白色面板上）

体检脚本对这三类都做了豁免。**所以纯标签请务必用 `text;` 开头的 style**，
否则会被当成重叠报出来。

## 缺陷 2：越出容器

形状有一部分在它所属的分层容器的边界之外。

**成因**：容器和内容分别手算，容器改小了但内容没跟着改。

**判据**（脚本用的就是这个）：如果一个形状 ≥ 60% 的面积落在某个容器的矩形里，
就认为它「属于」这个容器，此时要求它**完全**落在容器内（允许 `-Tolerance` 的宽容度）。

用 60% 而不是「中心点在容器内」，是因为中心点判据对「一多半探出去」的情况太宽松。

**修法**：

- 容器留内边距：容器高 120，里面的方框高 70，上下各留 25
- 横向同理，容器左右留 30~50 的边距
- 容器和内容一起算：先定容器，再把内容按容器内可用宽度等分

## 缺陷 3：连线穿框

一条边从 A 连到 B，路径**穿过了无关的第三个形状 C**。

**成因**：draw.io 的 `orthogonalEdgeStyle` 会自动走「横平竖直」的最短路径。
当 A 和 B 在**同一行**、而 C 夹在中间时，路由会直接横穿 C。

这不是 bug，是默认行为。它也是**最隐蔽**的一类缺陷：连线看起来「正常地」
从一个框连到另一个框，只有顺着线看才发现它压过了别人。

**修法**（按优先级）：

1. **指定出入边**，让线从正确的边出发：

   ```xml
   style="edgeStyle=orthogonalEdgeStyle;exitX=0.5;exitY=1;exitDx=0;exitDy=0;
          entryX=0.5;entryY=0;entryDx=0;entryDy=0;"
   ```

   `exitY=1` 是「从下边出去」，`entryY=0` 是「从上边进来」。上下走就绕开了同行的问题。

2. **加显式拐点**，把线推到方框行之外：

   ```xml
   <mxGeometry relative="1" as="geometry">
     <Array as="points">
       <mxPoint x="120" y="560" />   <!-- 拐到方框行下方的空白带 -->
       <mxPoint x="900" y="560" />
     </Array>
   </mxGeometry>
   ```

3. **改布局**：把互相连的模块排在同一列，让主流向从上到下，横向连线自然就少了。
   架构图尤其适用——「上层 → 下层」的纵向流向本来就不需要横向连线。

**脚本怎么判**：它按 draw.io 的规则近似出正交路径
（从 source 底边中心向下 → 在垂直空隙中间横移到 target 的中心 x → 向下进 target 顶边），
然后检查每条线段是否和**非容器**的形状相交。容器是允许穿过的——连线本来就该穿过层边界。

所以脚本报出来的「穿框」是**真的穿过了某个模块**，不是穿过了虚线层框。

## 缺陷 4：文字溢出

文字宽度超过方框的可用宽度。

**成因**：字号调大了、或者文案变长了，但方框宽度没跟着改。

**估算公式**（脚本用的，和实测比较接近）：

```
宽 = Σ 每个字符
      CJK（含中文标点、全角符号）→ 1.0 × fontSize
      其它（ASCII 字母数字符号） → 0.55 × fontSize
可用宽度 = 方框宽度 - 16   （左右各 8 像素内边距）
```

**为什么是「估算」**：真实宽度取决于字体、字重、字距，且 draw.io 有自动换行（`whiteSpace=wrap`）。
所以脚本报的是**可能溢出**，属于「值得看一眼」而不是「一定错了」。
有 `whiteSpace=wrap` 的方框会放宽判定——反正能换行。

**修法**：

- 加宽方框，或者调小 `fontSize`
- 长文案主动用 `&#10;` 手动断行，别指望自动换行在任意宽度下都好看
- 加 `whiteSpace=wrap` 允许换行
- 中文标签尽量控制在 6~8 个字以内

## 用法

```powershell
# 体检单个文件
.\scripts\Test-DrawioLayout.ps1 -Path .\架构.drawio

# 放宽容差，少报点无关紧要的
.\scripts\Test-DrawioLayout.ps1 -Path .\架构.drawio -Tolerance 6

# 只关心有没有问题，不要详细输出（给 CI 用，退出码 1 表示有问题）
.\scripts\Test-DrawioLayout.ps1 -Path .\架构.drawio -Quiet
```

退出码：`0` = 没发现问题，`1` = 有发现（或文件读不了）。
**只读，不修改你的文件。**

## 一点判断

体检报出来的东西**不是都要改**。它的定位是「把肉眼容易漏的地方指出来」，不是「必须全绿」。

真正该改的：

- 连线穿过了**承载语义的模块**（比如从「订单服务」穿到「用户服务」）——必改
- 文字明显放不下（估算超了 30% 以上）——必改
- 形状越出容器——必改

可以放过的：

- 文字估算超一点点（5% 以内）——字体实际更窄，多半没事
- 装饰性元素之间的轻微重叠——本来就该叠

**判断标准始终是「这图还能不能一眼看懂」，不是「脚本有没有全绿」。**
