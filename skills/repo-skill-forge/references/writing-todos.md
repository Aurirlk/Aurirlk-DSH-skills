# 把 TODO 写成有用的内容

生成器留下的每个 TODO 都是一句话的写作任务。这一节讲怎么把它写成"下一个人能直接用"的段落，
以及哪些写法等于没写。

## 判定标准只有一条

> **读完这段，另一个人能不能在不打开代码的情况下，知道该动哪个文件的哪一行？**

能，就是写好了。不能，就是没写。

## 三类 TODO 的写法

### 一、模块职责（`M-*-1`）

要求：2-3 句，说清"负责什么、不负责什么"，至少引用 2 个真实文件。

**做法**：先看这个模块的目录结构，找 2-3 个名字最像"门面"的类（Controller、Service、Handler），
读它们的 public 方法签名——方法名连起来就是这个模块的业务词汇表。

**反例**：

> 本模块负责智能体相关的核心业务逻辑，提供完整的增删改查能力。

问题：没有"不负责什么"，没有文件，换个模块名这段话照样成立。

**正例**：

> 本模块管智能体的**配置与生命周期**：创建、复制、上下架、绑模型（`AgentService#create` 在
> `.../service/agent/AgentService.java:88`，`AgentController` 只做参数校验后转调）。
> **不管**会话：对话状态在 `.../chat/` 下的 gateway 模块，本模块只提供 `agentId` 与模型路由信息。
> 结果：改对话行为不该动这里，改"智能体能选哪些模型"才动这里。

### 二、典型流转（`M-*-2`）

要求：4-6 步，从入口到落库/返回，每步带 `file:line`。

**做法**：用 `query.mjs callees <类名>` 拉第一跳，再顺着点进去。**不要通读**——只读被调用的那个方法。

**反例**：

> 请求进入 Controller，经过 Service 层处理，最终写入数据库。

问题：这句话对所有 CRUD 项目都成立，信息量为零。

**正例**：

> 1. `POST /api/agent` 进 `AgentController#create`（`.../AgentController.java:216`），只做 `@Validated` 校验。
> 2. 转 `AgentService#create`（`:88`），`@Transactional` 开启。
> 3. 先写 `agent`（`AgentMapper#insert`，`:102`），拿到自增 id。
> 4. 再写 `agent_app` 关联表（`:110`），失败则整体回滚——**注意这张表没有唯一约束，重复绑定不会报错**。
> 5. 返回前刷新本地缓存 `AgentCache#evict`（`:121`），缓存在多实例下是本地 Map，**跨实例不失效**。

第 4、5 步才是这段的价值：它们不是"流程"，是"读代码才知道的事"。

### 三、特有坑（`M-*-3`）

要求：2-3 条，每条都要能说"如果不这样会怎样"。

**做法**：找这些东西——`synchronized`/锁、`@Transactional` 的传播行为、缓存与失效、
时间与时区、分页边界（`page=0` 还是 `page=1`）、空集合与 `null` 的区别、并发下的幂等。

**反例**：

> 注意并发安全和事务一致性。

**正例**：

> - `AgentCache` 是本地 `ConcurrentHashMap`（`.../cache/AgentCache.java:14`），多实例部署时
>   只有当前实例失效。所以"改完立刻查"可能读到旧值，跨实例最长滞后 5 分钟（`@Scheduled` 全量刷新）。
> - 分页参数从 1 开始（`PageQuery` 内部 `offset = (page - 1) * size`，`:33`），
>   但前端有一个页面传的是 0——传 0 会变成负 offset，MySQL 直接报语法错。

## 什么时候可以不写

**允许**：读完相关代码，确实没发现特有风险 → 写"未发现特有风险（已读 `A.java`、`B.java`）"并删掉标记。

**不允许**：没读代码，写"待补充"、"TODO"、"视情况而定"。这类占位句会被后人当成"已经有人看过了"。

## 三条硬规矩

1. **不许写"应该"、"可能"、"建议"**。要么是事实（"这里用的是 XX"),要么标注为待确认并给出确认方法。
2. **每条结论一行，行尾给 `path:line`**。行内引用两个以上文件的，拆成两条。
3. **不要复述上面表格里已有的内容**。模块册前半部分已经有文件清单和端点表，TODO 部分只写"表格里看不出来的"。

## 补完自检

```bash
# ① 残留标记必须为 0
node <repo-skill-forge>/scripts/verify-skillpack.mjs <包根> --strict

# ② 抽查：随机挑 5 条带 file:line 的结论，逐个打开核对
# （脚本查不了"内容对不对"，只能查"路径在不在"。这一步只能人做。）

# ③ 引用路径的批量核对
node <repo-skill-forge>/scripts/verify-skillpack.mjs <包根>
```

校验器会告诉你"引用的文件不存在"，但**不会告诉你"引用的文件里没有这行代码"**。
后者要靠抽样。抽 5 条，错 1 条就说明整体需要重看。
