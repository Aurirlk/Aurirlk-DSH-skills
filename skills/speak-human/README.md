# speak-human

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

把研发视角的**技术实现**翻译成非技术读者一眼能看懂的**业务人话**。

产出的是"现在有什么功能、解决了什么麻烦"，不是"代码怎么改的"。

## 什么时候用

- 要把技术文档 / commit 记录 / Git Log / 需求文档写成给业务方、客户、管理层看的**产品介绍**或**更新日志**
- 输出被抱怨"太技术""看不懂""全是黑话"
- 用户直接说"说人话""翻译成人话"

## 两头都要守住

这是这个技能的核心张力：

| 极端 | 要求 |
|---|---|
| **绝不说技术黑话** | 默认读者不懂代码、数据库、接口、架构。不解释实现，只说功能与结果 |
| **绝不写公关废话** | 客观、克制、平实。禁堆营销形容词 |

多数"说人话"的尝试会滑向后者——**去掉了术语，换成了空话**，这同样不合格。

## 三步流水线

```
1 降噪与合并   → 同类项合成一条业务描述；纯内部事务过滤或并成一句
2 人话翻译     → 套公式：[场景] + [能做什么] + [确定结果]
3 红线词自检   → 逐字扫两个禁用词表，命中即替换
```

## 翻译公式

- **功能介绍**：`[核心动作/场景] + [具体能做什么] + [带来的确定结果]`
- **问题修复**：`修复了 [什么操作场景下] 出现 [什么具体异常现象] 的问题`

## 技术词降维示例

| 原词 | 译法 |
|---|---|
| 序列化 / 反序列化 | 数据读取 |
| 枚举 / 字段 | 选项 / 填写项 |
| 路由 | 页面跳转 |
| 鉴权 | 权限验证 |
| 异步队列 | 后台排队处理 |
| 熔断 failover | 主服务异常时自动切换备用线路 |
| RAG 混合召回 | 结合关键词与语义精准搜资料 |

**可保留的专有名词**：MySQL、Excel、OCR、URL——但首次出现时用大白话点明用途。

## 红线词库

这个技能内置两张禁用词表，覆盖了两类最常见的失败：

**研发黑话**：赋能、抓手、闭环、生态、矩阵、链路、颗粒度、沉淀、对齐、打通、降本增效、底层逻辑、痛点、兜底、契约层、高可用、异构、落库、回灌

**营销废话**：致力于、旨在、无缝衔接、革命性、颠覆性、突破性、全方位、一站式、显著提升、极大的、重磅推出、焕然一新、保驾护航

生成前必须逐字扫描，命中即替换为具体动词或业务名词。

## 改写示例

**技术原文**

> 模型管理支持密钥 SM4 加密落库、启停、作用域及多模型熔断 failover，候选链按默认优先排序，故障自动切下一家。

**人话**

> 系统密钥采用高强度加密存储；支持配置多个备用模型，当主模型出现网络波动或服务异常时，系统会自动切换至备用模型，保障业务不中断。

## 输出模板

技能内置两套模板：

- **场景 A · 产品功能介绍**：按模块分组，每条 = 核心能力短语 + 大白话说明
- **场景 B · 版本更新日志**：`优化` / `修复` 两节，修复类必须保留"什么场景 + 什么现象"
