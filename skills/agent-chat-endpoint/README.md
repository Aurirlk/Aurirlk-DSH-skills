# agent-chat-endpoint

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

流式对话端点看着简单：吐 token、发个结束帧。**真正上线后炸的都不是这两件事。**

炸的是换行被吃掉、答完还转圈、聊完没历史、上下文爆了开始胡说 —— 四个子系统，四类不同的根因。

## 什么时候用

- 正在做/改 agent 的流式对话端点（SSE、打字机效果）
- 用户反馈：**文字挤成一坨、表格格式全丢**
- 用户反馈：**回答完了还转圈 2-3 秒**
- 用户反馈：**能聊，但历史里一条都没有**
- 长会话越聊越傻，或者压缩之后丢最近几轮
- 同一个端点成功回音频、失败回 JSON，前端解析报错

## 四件套

```
① 增量映射   → 空白帧也是内容，别用 isBlank 过滤
② 收尾语义   → 额外模型调用一律独立端点，别挂流尾
③ 历史落库   → userId 在请求线程取；落库失败不拖垮对话
④ 上下文预算 → 边界用消息 id；压缩不改原历史
```

每条规则背后的真实症状、判据和改法，见 [SKILL.md](SKILL.md) 的「故障 → 判据对照表」——那张表可以直接拿去对着线上现象查。

## 三个最反直觉的点

1. **`isBlank()` 过滤会让 markdown 全体失效**。模型把 `"\n"` 单独成帧发出来，后端当"空增量"丢了，于是标题/表格/分隔线全部塌成一个段落。
2. **在 `completion` 之后做事等于没做**。前端见到结束帧就 `reader.cancel()`，后面的帧收不到；放在之前又会推迟收尾。
3. **`doFinally` 里取登录态必然为 null**。SSE 写线程不是请求线程 —— 这是"聊完没历史"最常见的根因。

## ⚠️ 边界

- 面向**自建对话端点**（SSE / chunked）。托管 API 的流式协议不在范围内
- 不绑定框架：规则本身与 Spring WebFlux、Node 流、FastAPI 都通用，示例偏 Java + Vue
- 「压缩」讲的是**投喂预算**，不是向量检索式的长期记忆（那部分见 agent-orchestration 的三层记忆）
