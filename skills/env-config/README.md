# env-config

> 本技能是 [Aurirlk DSH Skills](../../README.md) 合集的一员 · [← 返回仓库目录](../../README.md)

**中文** | [English](README.en.md)

配置缺了就把人引导到能跑起来。

## 这玩意儿治什么

Agent 干活干到一半，卡在"读不到 `.env` 里的路径"。

这时候最常见的两种烂处理：

- 直接一句「请先配置 `.env` 中的 `XXX_PATH`」——用户不知道填什么、填哪、填对了没。
- **更烂的**：变量为空就悄悄用默认值继续跑，二十分钟后在某个莫名其妙的地方报错。

这个技能做的是第三件事：**在进入主流程之前拦住，按三层把问题定位到具体某一项，然后带着用户填完、验完再走。**

## 三层检查

```
.env 存在?
  ├─ 否 → 复制 .env.example，没有才问用户
  └─ 是 → 变量有非空值?
           ├─ 否 → 列表一次问全，别挤牙膏
           └─ 是 → 值有效?
                    ├─ 否 → 按类型验证（路径 / URL / 端口 / 开关 / 密钥）
                    └─ 是 → 继续干正事
```

## 几个它较真的地方

**"有值"不等于"有值"**：`KEY=`、`KEY="  "`、`KEY=your-key-here`、`KEY=changeme` 全都算没配。占位符最坑——它看起来配好了，一路跑到调接口才炸，报错还指向别处。

**相对路径是个陷阱**：`./repo` 相对的是**进程工作目录**，不是 `.env` 所在目录。所以"我在 A 目录跑好好的，换 B 目录就找不到"——解法是改绝对路径，不是去改代码。

**密钥不回显**：写进文件后只说"已配置"，不在对话里打印原文。用户不想把 key 贴进对话的，就让他自己填，填完复查格式。

**CI 里没有 `.env`**：所以读配置的顺序必须是「进程环境变量 → `.env` → 默认值」。反过来（文件优先）会让 CI 静默用默认值，本地却正常——这种 bug 只在流水线上出现，最难查。

## 什么时候会用到

- 新同事第一次拉仓库，第一步就跑不起来。
- 换了机器 / 拷了别人的 `.env`，路径全不对。
- 技能内部需要工作目录、密钥、开关，但拿不到。
- 报错信息只说了"找不到文件"，实际是配置为空。

## 安装

```bash
# 整包
pnpm add github:Aurirlk/Aurirlk-DSH-skills

# 或只挂这一个
ln -s "$PWD/skills/env-config" ~/.dsh/skills/env-config
```

## 它不会做什么

- 不会替你编密钥。编出来的占位符是定时炸弹。
- 不会把 `.env` 提交进 Git。要先确认 `.gitignore` 里有它。
- 不会改代码去迁就错的配置。配置是外部输入，代码不该为它让步。
